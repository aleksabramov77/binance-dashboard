# Лаборатория: память прогонов `/flow lab`

Здесь живёт то, что лаборатория решила и почему — чтобы следующий разбор не начинался с нуля. Пишется процессом
`/flow lab` (`.config/flows/lab.yaml`), читается агентом `quant` перед каждым разбором. Метод — скилл
`trading-lab` (`.claude/skills/trading-lab/`), форматы — его `references/outputs.md`.

| Файл | Что | Кто пишет |
|---|---|---|
| [`journal.md`](journal.md) | Записи прогонов, новые сверху: период, рынок, решения, что применено, гипотезы | оркестратор `/flow lab`, этап journal |
| [`hypotheses.md`](hypotheses.md) | Все карточки гипотез `H<n>` со статусами и kill/success-критериями; одна строка — одна карточка навсегда | оркестратор, этап journal |
| `runs/<дата>/report.md` | Отчёт по сделкам эпохи: метрики, контекст рынка, семейства, подсказки | `pnpm lab:report` (руками не править) |
| `runs/<дата>/review.md` | Разбор: подозрительное, решения keep/mirror/tune/pivot/kill, действия | агент `quant` |
| `runs/<дата>/ideas.md` | Карточки гипотез прогона и отклонённые идеи | агент `quant` |
| `runs/<дата>/apply.md` | Что реально переключили в БД («было → стало») | `pnpm lab:apply --out` |

`report.json` и `trades.csv` прогона в git не попадают (`.gitignore`) — их всегда можно построить заново.

Данные о сделках — в БД (таблицы `paper_trades`, `experiments`), не здесь: журнал — про решения, а не про цифры.
Как читать цифры — `trading-lab/references/metrics.md`; почему эксперименты проигрывают — `failure-modes.md`.
