# 0060 · Статистика `/stats` по счетам Paper / Demo / Real

- **Тип:** feature (задача 4 эпика «Реальные деньги», часть 2; вместе с п. 12 очереди — задача C плана 0016)
- **Статус:** draft
- **Раздел PRD:** §3.7 [Реальный счёт (Live)](../PRD.md#37-реальный-счёт-live-)
- **Дата:** 2026-10-17

## Цель
`/stats` сейчас считает только paper-сделки. Пользователь хочет смотреть ту же статистику по каждому счёту —
Paper, Demo и Real — с теми же разрезами и фильтрами (группа активов, эксперимент, направление, монета, период),
чтобы видеть, где стратегия зарабатывает в симуляции, на демо-бирже и реальными деньгами.

## Решения пользователя (2026-10-17)
1. Счета показываются **переключателем** «Paper · Demo · Real»: вся страница (итог, лучшие и худшие, таблица
   разрезов) считается по выбранному счёту. Сравнения трёх счетов рядом нет.

## Сценарии
1. Пользователь открывает `/stats` → по умолчанию Paper, всё как сейчас.
2. Переключает на «Demo» → итог и таблица по сделкам демо-зеркала; фильтры и разрез сохраняются. Ссылка с
   `?account=demo` открывает сразу демо.
3. Переключает на «Real» → итог и таблица по реальным сделкам; PnL с комиссиями, Max DD в $. Реальных сделок
   нет → пустое состояние «На реальном счёте ещё нет закрытых сделок».
4. Фильтр «Рынок» = USDⓈ-M + разрез «Монета» на Demo → лучшие и худшие монеты демо-зеркала на фьючерсах.

## Критерии приёмки
- [ ] AC1. **Переключатель счёта** «Paper · Demo · Real» первым в панели фильтров (Tabs, как «Период»). Значение — в
  URL (`account`, по умолчанию `paper` без параметра); «Сбросить фильтры» счёт не сбрасывает.
- [ ] AC2. **Все разрезы** (эксперимент, рынок, монета, направление) **и фильтры** (рынок, эксперимент,
  направление, монета, период) работают на всех трёх счетах; итог, «Лучшие» / «Худшие» и таблица — по выбранному
  счёту. В заголовке итога — имя счёта.
- [ ] AC3. **Что считается по счетам:**

  | Метрика | Paper | Demo | Real |
  |---|---|---|---|
  | Сделки | как сейчас | закрытые демо-сделки (+ открытые) | закрытые реальные сделки (+ открытые) |
  | PnL | как сейчас | по ценам входа и выхода, без комиссий (как демо-колонки `/experiments`) | `realized_pnl` — по исполнениям с комиссиями (как Real-колонки); оценки — «≈» |
  | Комиссии | как сейчас | «—» (у демо их нет) | `fees_usd` |
  | Win rate, Profit factor | как сейчас | по закрытым | по закрытым с известным PnL |
  | Средний R | как сейчас | по стопу paper-сделки (как «Авто» в 0053) | по своему стопу (`stop_loss`), иначе стопу paper-сделки |
  | Max DD | % от бюджета, как сейчас | % от бюджета эксперимента (как демо-колонки) | **в $** (как Real-колонки) |
- [ ] AC4. **Период и эпохи.** «Эпоха» и «24 ч / 7 дней» работают для Paper и Demo по времени закрытия сделки (для
  Demo — ещё и после демо-сброса группы, как демо-колонки). Для Real эпох нет: выбор эпохи скрыт, «Эпоха» = всё
  время; 24 ч / 7 дней работают.
- [ ] AC5. **Описания колонок** и подпись над таблицей говорят, по какому счёту и как считается (PnL Demo без
  комиссий, Real — с комиссиями, Max DD Real — в $).
- [ ] AC6. **Пустые состояния:** у счёта нет сделок под фильтры — «Нет закрытых сделок на счёте <имя> за период».
  COIN-M на Real — «COIN-M на реальном счёте не торгуется».
- [ ] AC7. **Телефон (390 px):** переключатель помещается, страница без горизонтальной прокрутки, таблица
  прокручивается в своей рамке, как сейчас.
- [ ] AC8. **Глоссарий** (`docs/ai/glossary.md` → `pnpm glossary`): «Счёт на `/stats`» — что считается на каждом
  счёте.

## Вне scope
- Сравнение трёх счетов в одной таблице.
- Новые разрезы и метрики, изменения торговли.
- Страница эксперимента `/experiments/[id]`.

## Технические заметки
- **Мой выбор — сверить при утверждении:** по умолчанию Paper; Max DD Real в $, Demo — в %; эпохи для Real скрыты.
- **Данные:** Paper — как сейчас (`readTradeStats`); Demo — `demo_mirror_orders` (+ paper-сделка для стопа и R);
  Real — `live_mirror_orders`. Строки приводятся к общему виду `SliceTrade` и считаются тем же
  `filterTrades` / `sliceStats` / `computeStats` где возможно; отличия (комиссии, Max DD в $, оценки) — параметром
  счёта в чистых функциях с тестами.
- **SQLite (задача 0059):** параллельно база переводится на SQLite — только простые select через query builder
  drizzle, без сырого SQL и Postgres-функций, без новых колонок и миграций; расчёт в TS.
- **API:** `GET /api/experiments/stats?account=paper|demo|real` — Zod-схема запроса и ответа (`statsQuerySchema`,
  `tradeStatsResponseSchema` + поле `account`); без параметра — paper (старые ссылки работают).
- **UI:** `src/pages/stats/ui/StatsPage.tsx`, `src/pages/stats/model/useStatsView.ts` (nuqs). Пути UI-кита
  `@/shared/ui/<PascalCase>`.
- **Приватные эксперименты:** в spec, тестах и коммитах — только фиктивные id.
