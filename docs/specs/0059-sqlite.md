# 0059 · SQLite на VM вместо Supabase Postgres, перенос данных

- **Тип:** feature
- **Статус:** draft
- **Раздел PRD:** §3.4 Авто-бот (хостинг)
- **Дата:** 2026-10-17

## Цель
Шаг 3 переезда (после 0017, 0048, 0055). База приложения переезжает из Supabase Postgres в файл SQLite на VM
`apps-tokyo`: `/var/lib/binance/app.db`. После этого Supabase не нужен приложению; через неделю его можно отключить
(п. 24 очереди) и не переходить на тариф $25. Данных около 6 МБ (12 таблиц, больше всего в `app_logs` и `paper_trades`),
перенос занимает секунды. Торговля стоит около 5 минут.

## Сценарии
1. Владелец открывает сайт на VM и видит те же эксперименты, сделки, статистику, журнал, демо-зеркало и снимки Earn,
   что были в Supabase до переключения.
2. Тик движка, демо- и авто-зеркало, Earn, монитор работают на VM как раньше, но пишут в SQLite.
3. `/db` в Telegram и предупреждение о месте показывают размер файла базы и свободное место на диске VM, а не лимит
   Supabase.
4. Отчёты лаборатории по прод-данным строятся по свежей копии базы, скачанной с VM (`pnpm db:pull`).
5. Локальная разработка и тесты работают на SQLite: файл `data/app.db`, в тестах — база в памяти. PGlite убирается.

## Технические решения
- **Драйвер:** `better-sqlite3` 13 + `drizzle-orm/better-sqlite3`. Режим WAL, `busy_timeout`, `foreign_keys = ON`.
  Путь к файлу задаёт `DATABASE_PATH`: на VM `/var/lib/binance/app.db`, локально `data/app.db`.
  `DATABASE_URL` приложение больше не читает; его используют только скрипт переноса и `*-supabase.ts` до отключения
  Supabase.
- **Схема:** таблицы в `src/entities/*/model/db.ts` переходят на `sqlite-core`. Миграции начинаются заново,
  с `drizzle/0000_*.sql`; Postgres-миграции 0000–0016 удаляются (они остаются в истории git). Типы:
  - `timestamp` → `integer` в миллисекундах (`mode: "timestamp_ms"`), в коде остаётся `Date`;
  - `doublePrecision` → `real`;
  - `jsonb` → `text` (`mode: "json"`);
  - `boolean` → `integer` (`mode: "boolean"`);
  - `serial` и `bigserial` → `integer` primary key.
- **Postgres-SQL в запросах:**
  - `now()` заменяется на время из JS (`new Date()`), `now() - make_interval(...)` — на вычисленную дату;
  - `->>` остаётся, SQLite его понимает; `::int`, `::jsonb`, `'-infinity'::timestamptz` убираются;
  - слияние `jsonb ||` → `json_patch`.
- **Транзакции и блокировки:**
  - В better-sqlite3 транзакции синхронные. Четыре асинхронные транзакции (`settingsDb` ×3, `liveAutoDb`)
    переписываются на синхронный вид, внутри них нет сетевых вызовов.
  - Advisory-блокировки тика (`tickLock`) и прогона зеркала (`mirrorLock`) заменяются блокировкой в процессе: процесс
    с базой один.
  - Воркер `binance-live` ходит в приложение по HTTP и базу напрямую не открывает.
- **Место в БД (`dbSpace`):**
  - Используется = размер файла базы с WAL; лимит = размер файла + свободное место на диске (`statfs`).
  - Самые большие таблицы берутся через `dbstat`.
  - Пороги и тексты уведомлений (spec 0021) не меняются.
- **Сборка:** `better-sqlite3` добавляется в `onlyBuiltDependencies` pnpm и в `serverExternalPackages`. Нативный
  модуль собирается в CI (ubuntu x64, Node 22) и подходит VM (x86_64, Node 22.23).
- **Перенос:** скрипт `pnpm db:import-pg --to <файл>` читает все 12 таблиц из Supabase (`DATABASE_URL` из
  `.env.local`) и пишет их в новый файл SQLite с применёнными миграциями.
  - После записи сверяет по каждой таблице число строк, а для `paper_trades` и `demo_mirror_orders` — суммы PnL.
  - Исходная база не меняется.
- **Скрипты лаборатории:**
  - `lab:report` получает флаг `--prod`: сначала `pnpm db:pull` скачивает снимок прод-базы по SSH
    (`sqlite3 .backup` на VM → `data/prod.db`), затем отчёт строится по нему.
  - `lab:apply` и `lab:private --prod` в этом PR в прод не пишут: выходят с подсказкой, что тумблеры есть на
    `/experiments` и `/settings`. Запись в прод с ноутбука — отдельная задача, она добавляется в очередь PRD.

## Откат
В течение недели: ручная выкатка предыдущего коммита (Actions → Deploy, выбор ref) с `DATABASE_URL` в `app.env`.
Paper-сделки и журнал, записанные в SQLite после переключения, при откате теряются. Демо-ордера на бирже остаются,
а зеркало их сверяет.

## Вне scope
- Ночные бэкапы `sqlite3 .backup` (п. 23). До них данные защищают ежедневные снимки Lightsail.
- Ключ реального счёта в базе (п. 22); выкатка `binance-live` (п. 20).
- Отключение Supabase и удаление `supabase/`, edge-функций и `*-supabase.ts` (п. 24, с согласия владельца).
- Hono и Vite вместо Next.js.
