# 0065 · Read-only ключ основного аккаунта: ввод на сайте, хранение в базе в зашифрованном виде

- **Тип:** feature
- **Статус:** in-progress
- **Раздел PRD:** §3.4 Авто-бот (хостинг), очередь задач п. 22
- **Дата:** 2026-10-17

## Цель
После переезда на VM у прода нет read-only ключа основного аккаунта Binance: в `/etc/binance/app.env` нет
`BINANCE_API_KEY`/`BINANCE_API_SECRET`. Поэтому сейчас:
- «Портфель» показывает инструкцию по подключению вместо балансов;
- в Earn нет вкладок сложных продуктов (Dual, DeFi, стейкинг);
- воркер реального счёта пропускает проверку, что `dashlive` — субсчёт именно основного аккаунта: без ключа UID
  основного счёта неизвестен.

Решение владельца от 2026-10-15: ключ хранится в базе в зашифрованном виде (AES-GCM), мастер-ключ лежит в файле на
сервере, а не в env. Владелец вводит ключ сам на странице «Настройки». Сам ключ после сохранения больше нигде не
показывается: ни на сайте, ни в журнале, ни в ответах API.

## Сценарии
1. «Настройки» → новая карточка «Основной аккаунт — read-only ключ». В ней поля «API Key» и «Secret Key» и кнопка
   «Проверить и сохранить».
2. Сервер проверяет ключ в Binance (`GET /sapi/v1/account/apiRestrictions`, вес 1), прежде чем сохранить. Ключ
   принимается, только если:
   - включено «Enable Reading»;
   - включено «Restrict access to trusted IPs only»;
   - выключены вывод, внутренние и универсальные переводы, торговля Spot/Margin, Futures и Margin, опционы
     («Enable Vanilla Options») и Portfolio Margin («Enable Portfolio Margin Trading»; этих двух полей в ответе
     Binance может не быть — тогда они считаются выключенными).

   Иначе ключ не сохраняется, а в карточке видны причины (как у ключа воркера, spec 0047), например «у ключа разрешён
   вывод средств — выключите «Enable Withdrawals»». Если Binance не ответил или отклонил запрос (неверный ключ, IP не
   в списке), ключ тоже не сохраняется, а в карточке видна ошибка Binance.
3. Ключ сохранён — в карточке видно:
   - «Ключ …AB12» (последние 4 символа API Key);
   - когда сохранён;
   - права: строки «да/нет» по каждому флагу.

   Полей с ключом больше нет, есть кнопки «Заменить ключ» и «Удалить ключ».
4. Сразу после сохранения «Портфель» и Earn работают без перезапуска сервиса. Воркер получает UID основного счёта при
   следующем пульсе (не позже чем через час, это TTL кэша UID).
5. «Удалить ключ» — ключ стирается из базы, «Портфель» снова показывает инструкцию. Удаляет сам владелец.
6. Мастер-ключ пропал или сменился, и ключ из базы не расшифровывается. Тогда приложение не падает: карточка пишет
   «Сохранённый ключ не расшифровывается — введите его заново», «Портфель» ведёт себя так, будто ключа нет, в журнале
   одна запись `account-key.decrypt-failed`.
7. Локально (`pnpm dev`, `pnpm wt serve`) ничего не меняется: если в базе ключа нет, берётся `BINANCE_API_KEY` из
   `.env.local`.

## Технические решения
- **Шифрование** — `node:crypto`, AES-256-GCM:
  - на каждую запись новый случайный IV (12 байт);
  - AAD — имя записи (`binance-main`), чтобы шифротекст нельзя было переставить в другую запись;
  - шифруется JSON `{ apiKey, apiSecret }`, в базе хранятся `iv`, `tag` и шифротекст (base64).
  - Модуль `src/shared/crypto/aesGcm.server.ts` (свой сегмент shared, как `shared/db`: в `shared/lib` Steiger ограничивает число модулей) — чистые функции `encrypt` / `decrypt` с тестами: круг
    шифрования, чужой мастер-ключ → ошибка, подмена шифротекста, тега или AAD → ошибка.
- **Мастер-ключ** — файл `/etc/binance/master.key`:
  - 32 случайных байта (base64), `root:binance 0640`;
  - путь задаётся в `SECRETS_KEY_FILE` в `app.env` (новый параметр — в `.env.example` и `.env.local` по правилам);
  - создаёт его `scripts/server/add-project.sh`; если файл уже есть, повторный запуск его **не перезаписывает**.

  Файл не входит в ночные бэкапы базы, поэтому утёкший бэкап без мастер-ключа бесполезен. Снимки Lightsail содержат
  весь диск, и после восстановления из снимка ключ работает. Если в env нет `SECRETS_KEY_FILE` или файла, ввод на
  сайте недоступен («на сервере не задан мастер-ключ»), а ключ из env, если он задан, работает как раньше.
- **База** — таблица `account_keys`, новая миграция Drizzle:
  - `name` (PK, пока только `binance-main`);
  - `ciphertext`, `iv`, `tag`;
  - `key_hint` — последние 4 символа API Key;
  - `restrictions` (JSON с флагами на момент проверки);
  - `saved_at`.
- **Слайсы FSD:**
  - Новая сущность `entities/account-key`:
    - `model/db.ts` — таблица;
    - `api` — `getMainCredentials()` с порядком «база → env → нет ключа», кэшем в процессе и сбросом кэша при
      сохранении и удалении, плюс хук статуса для карточки.
  - `getMainCredentials()` синхронная (better-sqlite3 синхронный), поэтому вызовы в `loadPortfolio`,
    `loadAdvancedCatalog` и `liveAccount` (`getMainAccountUid`) меняются на неё без перестройки кода.
    `getBinanceCredentials()` из `env.server.ts` остаётся источником «env» внутри неё.
  - Новая фича `features/manage-account-key`: форма (React Hook Form + Zod), мутации TanStack Query.
  - Карточка встраивается в `pages/settings`.
- **API** `app/api/account-key/route.ts` (за общим входом владельца):
  - `GET` — статус: есть ли ключ, `key_hint`, `saved_at`, права, откуда ключ (база / env / нет), доступен ли ввод.
    Без ключа и секрета.
  - `PUT` — проверить в Binance и сохранить. Только `Content-Type: application/json`, тело по Zod-схеме.
  - `DELETE` — удалить.
  - Оценка прав — по образцу `liveRestrictions.ts`. Правила другие (для чтения, а не для торговли), поэтому это
    отдельный набор правил рядом, без правки правил воркера.
- **Журнал:** `account-key.saved`, `account-key.rejected` (с причинами), `account-key.deleted`,
  `account-key.decrypt-failed`. В записях только `key_hint`, без ключа и секрета. Тест: ни ключ, ни секрет не
  попадают в журнал, ответы API и тексты ошибок.
- **Тексты:** в облаке `PortfolioPage` и `AdvancedAccessNotice` вместо «добавьте в .env» пишут «введите ключ в
  Настройках» со ссылкой. Локально подсказка про `.env.local` остаётся.
- **Документация:**
  - `docs/ai/deploy-lightsail.md` — раздел «Ключ основного аккаунта»: где мастер-ключ, что будет при его потере, как
    заменить ключ;
  - `src/shared/api/binance/README.md` — источник ключа.
- **Стоимость:** бесплатно, ничего платного не подключается.

## Критерии приёмки
Код (PR):
- [ ] AC1. `aesGcm.server.ts` — шифрование и расшифровка с тестами: круг, чужой мастер-ключ, подмена шифротекста,
  тега или AAD.
- [ ] AC2. Таблица `account_keys` + миграция; `getMainCredentials()`: база → env → нет. Кэш сбрасывается при
  сохранении и удалении. При ошибке расшифровки поведение «нет ключа» + одна запись в журнале. Тесты на in-memory
  SQLite.
- [ ] AC3. `GET` / `PUT` / `DELETE /api/account-key`. В `PUT` проверка прав: ключ с торговлей, выводом, переводами
  или без ограничения по IP отклоняется с причинами. Ответы Binance — заглушки в тестах.
- [ ] AC4. Карточка в «Настройках»: ввод, причины отказа, статус «…AB12», замена, удаление; без мастер-ключа ввод
  недоступен с объяснением. Проверено тестировщиком на `pnpm wt serve` (Binance — заглушка или ключ с отказом).
- [ ] AC5. «Портфель», Earn advanced и UID основного счёта для воркера берут ключ через `getMainCredentials()`.
  Тексты подсказок обновлены.
- [ ] AC6. Ключ и секрет не попадают в журнал, ответы API, тексты ошибок и клиентский бандл (тест + проверка
  тестировщиком).
- [ ] AC7. `add-project.sh` создаёт мастер-ключ и не перезаписывает существующий. Раздел в `deploy-lightsail.md`,
  `.env.example` и `.env.local`, README Binance, PRD (п. 22 очереди → 🚧 0065).
- [ ] AC8. `pnpm check`, `pnpm build` зелёные.

На VM (после мержа):
- [ ] AC9. Claude создаёт мастер-ключ на VM (повторный запуск `add-project.sh` или та же команда вручную) и
  добавляет `SECRETS_KEY_FILE` в `app.env`. Перезапуск сервиса — в секунды 25–50 минуты.
- [ ] AC10. Владелец создаёт в Binance read-only ключ с ограничением по IP VM и вводит его в «Настройках». Точные
  шаги в интерфейсе Binance Claude сначала проверяет в браузере и только потом даёт владельцу. После этого
  «Портфель» показывает балансы, в Earn есть сложные продукты, а у воркера в карточке «Реальный счёт» нет пометки
  «UID основного счёта неизвестен».

## Вне scope
- Шифрование других секретов (демо-ключи, торговый ключ воркера, токены) — они остаются в env.
- Смена мастер-ключа с перешифровкой (при потере — просто ввести ключ заново).
- Удаление старого ключа с Vercel — вместе с отключением Vercel (п. 24 очереди, только с согласия владельца).
