# 0029 · Фильтры режима BTC и торговых часов в экспериментах; строгая схема конфига; юниверс без акций и металлов

- **Тип:** feature
- **Статус:** testing
- **Раздел PRD:** §3.4 Лаборатория; «5a. Очередь задач», строка 2
- **Дата:** 2026-10-15

## Цель
Эксперимент лаборатории может торговать только в нужном режиме рынка (по BTC на старшем таймфрейме) и в нужные часы
и дни; конфиг с опечаткой или неизвестным полем не принимается молча; в юниверс не попадают токенизированные акции,
металлы и индексы — только крипта.

## Решения пользователя (2026-10-15)
- Очередь работ до эпохи 2 лаборатории ведёт сессия лаборатории; ТЗ и приёмку проходит сама, мерж — после тестов,
  ревью и CI (разрешение пользователя для этой очереди).
- Фильтр часов — строительный блок; час входа пока только записывается (задача A), а не подбирается под одну эпоху.
- Параметры удачных комбинаций — только в `private/experiments.json` (spec 0015); в этом spec и тестах — фиктивные примеры.

## Сценарии
1. Конфиг эксперимента с `marketFilter` → вход разрешён, только если режим BTC на закрытой свече старшего ТФ
   совпадает с условием для этого направления (например, long — BTC выше EMA(200) 4h, short — ниже; опционально
   ADX ≥ порога). Нет данных BTC → вход запрещён (как у `trendFilter`), сделки выходят как обычно.
2. Конфиг с `sessionFilter` → вход только в заданные часы UTC (`[from, to)`, через полночь — тоже) и дни недели.
3. `/experiments` и `/experiments/[id]` → в описании конфига строки «Режим рынка: …» и «Часы: …» (`describeConfig`).
4. `pnpm lab:private --dry-run` с неизвестным полем в `config` (например, опечатка `marketFiltr`) → ошибка с путём
   поля, в БД ничего не пишется.
5. Тик движка → токенизированные акции (spot: `SNDKB`, `SOXLB`, `CRCLB`, `SPCXB` …), металлы (`PAXG`, `XAUT`, `XAU`,
   `XAG`…), индексы и прочие не-крипто активы не входят ни в один юниверс; уже открытые по ним сделки закрываются
   своими выходами, как обычно.

## Критерии приёмки
- [x] AC1. `experimentConfigSchema` (`packages/trading-core/src/experiment.ts`) — новые необязательные поля:
  `marketFilter` { `symbol` (по умолчанию `BTCUSDT`), `timeframe`, `ema` (период), `minAdx?`, `long`: `above|below|any`,
  `short`: `above|below|any` } и `sessionFilter` { `hoursUtc?`: [from, to), `days?`: 0–6 (UTC) }. Старые конфиги без
  полей работают без изменений (тест на каталог).
- [x] AC2. Схема конфига строгая (`.strict()` на объектах конфига, входа, выхода, юниверса, фильтров): неизвестное
  поле — ошибка валидации с путём. Сид каталога, чтение `experiments` из БД и `lab:private` проходят на текущих данных
  (прод-формат), тест на «опечатку в поле → ошибка».
- [x] AC3. Чистые функции в `trading-core` с тестами: `marketRegimeAllows(btcCandles, filter, direction)` (EMA и ADX
  по закрытым свечам, без заглядывания вперёд) и `sessionAllows(time, filter)` (включая окно через полночь и дни).
- [x] AC4. Движок (`src/features/paper-engine/model/runTick.ts`): фильтры применяются к входу рядом с `trendAllows`;
  свечи BTC старшего ТФ берутся из кэша тика (один запрос на тик на ТФ, не на эксперимент); Edge Function
  `engine-tick` собирается (`pnpm check:edge`).
- [x] AC5. `describeConfig` — строки «Режим рынка» и «Часы/дни» на русском; глоссарий/справка — если там описаны поля
  конфига.
- [x] AC6. Юниверс: `isEligibleSymbol` / `pickUniverse` (`src/features/paper-engine/lib/universe.ts`) исключают
  не-крипто: futures — по `exchangeInfo` (`underlyingType !== "COIN"` или подтип `RWA`); spot — по списку
  `NON_CRYPTO` в `config/engine.ts` (как `STABLECOINS`), в него — известные токенизированные акции и металлы.
  Тест: тикеры с такими символами не попадают ни в `top`, ни в `movers`.
- [x] AC7. README движка и `trading-core` — абзац о фильтрах и исключении не-крипто.

## Вне scope
- Выбор параметров фильтров для конкретных экспериментов — приватно, после выкатки (`/flow lab`).
- Фильтр по режиму самой монеты — уже есть (`trendFilter`).
- Переразметка прошлых сделок по не-крипто символам.

## Технические заметки
- Сейчас схема — zod `object` без `strict`: неизвестное поле молча отбрасывается, и эксперимент с ещё не
  поддерживаемым полем запустился бы без него (найдено при подготовке эпохи 2).
- Futures `exchangeInfo`: `underlyingType` ∈ {COIN, …}; акции/металлы/индексы — не `COIN` (TSLAUSDT, XAUUSDT,
  BTCDOMUSDT…), PAXG/XAUT — `COIN` с подтипом `RWA`. Spot `exchangeInfo` такого признака не имеет.
- Возможный конфликт с PR #61 (0023: `futures` → `usdm`, COIN-M) — минимальные правки в общих файлах.
