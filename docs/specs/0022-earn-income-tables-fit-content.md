# 0022 · Доход Earn в «Где лежат деньги» и таблицы по ширине содержимого

- **Тип:** feature (включает исправление правила ширины из задачи 0018)
- **Статус:** approved
- **Раздел PRD:** §3.2 «Портфель», §2 «Оформление»
- **Дата:** 2026-10-15

## Цель
1. В таблице «Где лежат деньги» на `/portfolio` у Earn-позиций видны только ставка и доход за год. Пользователь хочет
   видеть, сколько Binance начислил за вчера и сколько позиция приносит в день и в месяц по текущей ставке.
2. Задача 0018 растянула все таблицы на всю ширину — пользователя поняли неправильно. Таблица должна быть шириной
   по своему содержимому; если содержимое шире доступного места — таблица занимает всю доступную ширину, а то, что
   не влезает, прокручивается вбок.

## Решения пользователя (2026-10-15)
1. «Для Earn добавь колонку Заработано за вчера, плановый доход в день, в месяц. Названия колонок можешь немножечко
   поменять».
2. «Заработано за вчера» — **из истории начислений Binance** (точная сумма: у Flexible базовая ставка и бонусные
   ступени, у Locked — свои начисления), за **вчерашние сутки по UTC** (так начисляет Binance). Если запрос истории не
   прошёл — в колонке «—», страница работает.
3. «Таблица не должна растягиваться на всю ширину. Если контента не так много, то выводи таблицу такой ширины, какой
   она является. Но если контента будет очень много, то заполняй ей всю доступную ширину экрана. Всё, что не влезает,
   скроллим по горизонтали». Заменяет решения 1, 5, 6 и 7 из [spec 0018](0018-tables-full-width.md).
4. Таблица шире доступного места — **сразу горизонтальный скролл**: заголовки колонок и названия (в том числе
   эксперимента) не переносятся, всегда в одну строку.
5. Таблицы внутри карточек (`/settings` — Paper- и демо-счета; журнал сделок; `/signals` — рост и падение) —
   **карточка сужается по таблице**, но не уже своего заголовка и кнопок; широкая таблица — карточка на всю ширину,
   таблица прокручивается внутри.
6. Остаётся из 0018: страница и шапка приложения без ограничения 1280 px; липкая шапка таблицы, пока видна хоть одна
   строка (если таблица помещается); узкий экран — прокрутка вбок внутри рамки, а не всей страницы.

## Сценарии
1. Пользователь открывает `/portfolio` (локально, с ключом) → в «Где лежат деньги» у USDT Flexible видит «Вчера» $1,23,
   «План / день» $1,25, «План / мес» $38,02, «План / год» $456,25; у Spot-строки во «Вчера» «—», в плане $0,00.
2. Сортирует по «Вчера» — сверху позиции, принёсшие больше всего вчера.
3. На мониторе 1920 px таблица портфеля (7 колонок) занимает столько, сколько нужно её колонкам, рамка не тянется
   до правого края.
4. На 1024/768 px таблица экспериментов (больше 15 колонок) не влезает → она на всю ширину страницы и прокручивается
   вбок внутри рамки; названия экспериментов и заголовки в одну строку.

## Критерии приёмки
Таблицы приложения: `/experiments` — эксперименты; `/experiments/<id>` — сделки; `/stats` — разрезы;
`/settings` — Paper-счета и демо-счета; `/portfolio` — активы; `/earn` — Simple Earn, Dual Investment, «Стейкинг
и DeFi»; `/signals` — рост, падение и журнал сделок; `/help` — таблица справки.

- [ ] AC1. `/portfolio`, «Где лежат деньги»: после «Ставка» колонки «Вчера», «План / день», «План / мес», «План / год»
  (бывшая «Доход / год»). У Flexible и Locked: «План / день» = ≈USD × ставка / 365, «План / мес» = ≈USD × ставка / 12,
  «План / год» = ≈USD × ставка (сверка на 2 строках). У Spot и Funding во «Вчера» «—», в плане $0,00.
- [ ] AC2. «Вчера» у Earn-позиции = сумма начислений Binance по этой позиции за вчерашние сутки UTC в долларах
  по текущей цене актива награды (Flexible — все виды начислений по монете, Locked — по позиции). Нет начислений —
  $0,00. Запрос истории не прошёл — во «Вчера» «—» у всех строк, остальная таблица и страница работают (unit-тест).
- [ ] AC3. Новые колонки сортируются по клику, у каждой в меню колонки есть описание (у «Вчера» — что это сутки UTC
  и пересчёт по текущей цене). Сохранённая ранее сортировка по «Доход / год» продолжает работать для «План / год».
- [ ] AC4. Окно 1920 и 1440 px: таблица, содержимое которой уже доступного места (портфель, все вкладки `/earn`,
  Paper- и демо-счета, рост/падение, журнал сделок, `/stats`, `/help`), — шириной по содержимому: правая граница рамки сразу за последней колонкой,
  пустых растянутых колонок нет. Заголовки колонок — в одну строку.
- [ ] AC5. Таблица шире доступного места (`/experiments` на 1024 и 768 px, любая не влезающая на 390 px) занимает всю
  ширину страницы и прокручивается вбок внутри своей рамки; страница целиком вбок не прокручивается; названия
  экспериментов, бейджи и заголовки колонок — в одну строку (нет переноса ни на одной ширине).
- [ ] AC6. Липкая шапка: таблица, которая помещается и длиннее экрана (`/experiments` на 1920 px, 40 строк), — при
  прокрутке вниз шапка у верхнего края окна, пока видна хоть одна строка; шапка непрозрачна, меню колонки
  открывается. Для прокручиваемой вбок таблицы шапка может не липнуть к окну (как в 0018).
- [ ] AC7. Карточки с таблицами (`/settings`, `/signals`, журнал сделок) сужаются по таблице, но не уже своего
  заголовка и кнопок; текст в карточке не налезает и не обрезается.

## Вне scope
- Итоговая строка (суммы по колонкам) в таблице портфеля — в сводке портфеля уже есть доход за год.
- «Вчера» для Spot/Funding (там нет начислений Earn), история за другие дни, график начислений.
- Изменение сводки портфеля и плана «Куда переложить».

## Технические заметки
- Затронутые слайсы: `shared/api/binance` (клиент и схемы истории начислений), `features/load-portfolio`
  (окно вчера по UTC, агрегация наград), `entities/holding` (поле `yesterdayUsd`, функция планового дохода),
  `widgets/holdings-table`, `shared/ui/table` (+ `table-fit`), страницы и виджеты с таблицами.
- Binance: `GET /sapi/v1/simple-earn/flexible/history/rewardsRecord` (параметр `type` обязателен: `BONUS`,
  `REALTIME`, `REWARDS`) и `GET /sapi/v1/simple-earn/locked/history/rewardsRecord`, окно `startTime`/`endTime`,
  страницы по 100. Вес — 150 на запрос: +3–4 запроса на загрузку портфеля, в пределах лимита SAPI. Какие типы
  Flexible суммировать без дублей — проверить пробой на реальном аккаунте, итог записать сюда.
- Locked-позицию сопоставлять с начислением по `positionId` (сейчас в Holding только `projectId`).
- Таблица: `<table>` шириной по содержимому (`w-max`), рамка `w-fit max-w-full`, прокрутка вбок в контейнере таблицы;
  режим `wrap` из 0018 убрать (`table-fit.ts`); общая рамка — компонент `TableFrame` в `shared/ui/table`.
- Ключ есть и на Vercel (портфель на проде работает): запросы истории пойдут и с IP Vercel. Чтобы не повторить бан
  IP из 0014 — тот же `fetchRetry` с паузой после 429/418, а награды за вчера кэшируются до следующей UTC-полуночи
  (за прошедшие сутки они не меняются): повторные загрузки портфеля историю не запрашивают.
- AC1–AC3 проверяются на локальном сервере worktree с ключом из `.env.local`, после выкатки — на проде.
- **Итог пробы (2026-10-15, read-only ключ, окно 14.10 00:00–23:59:59.999 UTC и 3/30 дней):**
  - Flexible: без `type` → `-1102`. `REALTIME` — одна строка на продукт за сутки (`time` 23:59:59 UTC), совпадает
    с `yesterdayRealTimeRewards` позиции; `BONUS` — начисление бонусной ступени в течение суток (у USDT ровно
    500 × 4 % / 365 = 0,05479); `REWARDS` — пусто и за 30 дней. В актуальной документации есть `type=ALL`: на пробе он
    отдал ровно объединение `BONUS` (3) + `REALTIME` (7) = 10 строк без повторов.
  - **Решение:** один запрос `type=ALL` вместо трёх (вес 150 у каждого), суммируются только `BONUS` + `REALTIME`
    (`FLEXIBLE_REWARD_TYPES`); `REWARDS` не учитывается, чтобы не задвоить суммы, если Binance начнёт его заполнять.
  - В ответе id продукта — `productId` (в документации `projectId`); схема берёт любое. Начисления Flexible
    сопоставляются с позицией по `productId` (строка без id — по монете), а не только по монете: так награда в другой
    монете не потеряется. Сумма — в монете `asset` награды, в USD — по её цене.
  - Locked: на аккаунте пробы Locked-позиций нет, история за 30 дней пуста; поля — по документации
    (`positionId` числом, `asset`, `amount`, `time`, `type`). Сопоставление — по `positionId`.
  - Итого на загрузку портфеля +2 запроса истории один раз за UTC-сутки на процесс (кэш по началу окна;
    сбой не кэшируется — следующая загрузка пробует снова).
