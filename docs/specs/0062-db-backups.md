# 0062 · Ночные бэкапы базы SQLite и чистка файлового журнала на VM

- **Тип:** feature
- **Статус:** draft
- **Раздел PRD:** §3.4 Авто-бот (хостинг)
- **Дата:** 2026-10-17

## Цель
С переезда на SQLite (spec 0059) вся база — один файл `/var/lib/binance/app.db` на VM. Сейчас его защищают только
ежедневные снимки всего сервера Lightsail (00:00 UTC). Снимок спасает при потере VM, но не при порче базы или ошибочной
записи: откатить один файл на вчерашний день нельзя без восстановления всего сервера. Нужны свои ночные копии базы:
быстро вернуть файл на нужный день и скачать копию на Mac. Заодно — чистка файлового журнала `LOG_DIR`, который сейчас
не удаляется (~0,5 МБ в сутки).

## Сценарии
1. Каждую ночь в 23:30 UTC (до снимка Lightsail в 00:00, чтобы свежая копия попала и в снимок) делается согласованная
   копия базы, проверяется и сжимается. Хранятся последние 7 копий.
2. Владелец или Claude восстанавливает базу из копии нужного дня по runbook: остановка сервиса, замена файла, запуск.
3. `pnpm db:pull --backup [ГГГГ-ММ-ДД]` скачивает ночную копию на Mac (по умолчанию — последнюю) для проверки или
   отчёта.
4. Сбой бэкапа виден: смоук `/flow release` падает, если последней копии больше 26 часов; строка в журнале сервиса.
5. Файлы журнала `app-YYYY-MM-DD.jsonl` старше 14 дней удаляются той же ночной задачей.

## Технические решения
- **Скрипт `scripts/server/db-backup.sh`** (на VM — `/usr/local/bin/binance-db-backup`, запускается от `binance`):
  1. `sqlite3 /var/lib/binance/app.db ".backup /var/lib/binance/backups/app-YYYY-MM-DD.db.part"` — согласованная копия
     без остановки сервиса (режим WAL);
  2. `pragma integrity_check` копии = `ok`, иначе ошибка и копия удаляется;
  3. `gzip` → `app-YYYY-MM-DD.db.gz` (атомарно через `.part`), права 600;
  4. удаляются копии старше 7 последних и файлы `LOG_DIR` старше 14 дней;
  5. итог — одна строка в stdout (journald): размер, длительность; ошибка — код выхода ≠ 0.
- **systemd:** `binance-backup.service` (oneshot, `User=binance`, `Nice=10`) и `binance-backup.timer`
  (`OnCalendar=*-*-* 23:30:00 UTC`, `Persistent=true` — пропущенный запуск догоняется после перезагрузки).
  Ставит `scripts/server/add-backup.sh binance` (повторный запуск безопасен); каталог `/var/lib/binance/backups` (700).
- **Место:** база ~5 МБ, сжатая копия ~1–2 МБ, 7 копий — до ~15 МБ. Свободно 14 ГБ.
- **Смоук (`scripts/server/smoke.sh`):** последняя копия в `/var/lib/binance/backups` не старше 26 ч (пока копий нет —
  предупреждение, не ошибка).
- **`pnpm db:pull --backup [дата]`:** скачивает `app-<дата>.db.gz` по SSH, распаковывает в `data/backup-<дата>.db`,
  `quick_check`.
- **Вне VM копии не уходят:** при потере VM база восстанавливается из снимка Lightsail (там и свежая ночная копия).
  Внешнее хранилище (другой провайдер) — отдельное решение, если владелец захочет.
