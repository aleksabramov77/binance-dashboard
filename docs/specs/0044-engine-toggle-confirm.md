# 0044 · Подтверждение тумблера «Автоторговля», журнал и Telegram

- **Тип:** feature
- **Статус:** approved
- **Раздел PRD:** §3.4 Авто-бот → Лаборатория экспериментов
- **Дата:** 2026-10-16

## Цель
Тумблер «Автоторговля» сейчас переключает движок лаборатории одним кликом. Случайное выключение опасно: выключенный
движок пропускает тик целиком — не открывает сделки **и не проверяет стопы/тейки открытых paper-сделок**; после
включения выходы догоняются по пропущенным 1m-свечам (задача 0028), то есть закрываются задним числом, а демо-позиции
зеркало закроет по текущей цене. Нужно подтверждение с понятными последствиями, след в журнале и уведомление в Telegram.

## Сценарии
1. Пользователь нажимает тумблер «Автоторговля» (включён) в шапке или в `/settings` → Paper → открывается модалка
   с числом открытых paper-сделок и демо-позиций и красной кнопкой «Выключить». «Отмена» — ничего не меняется.
2. Пользователь нажимает тумблер (выключен) → модалка «Включить автоторговлю?» с одной кнопкой «Включить».
3. После любого переключения в `/logs` видна запись: что сделано, кто (логин GitHub; локально — «вход выключен»),
   откуда (UI), и в Telegram приходит сообщение «Автоторговля выключена в HH:MM UTC» / «… включена в HH:MM UTC».

## Критерии приёмки
- [ ] AC1. Клик по включённому тумблеру не выключает движок сразу: открывается модалка (shadcn/ui `Dialog` из
  `shared/ui`, оформление как у `ConfirmAction` в `/settings`) с заголовком «Выключить автоторговлю?» и текстом
  «Открыто N paper-сделок и M демо-позиций — их стопы и тейки перестанут проверяться до включения». Кнопки «Отмена»
  (outline) и «Выключить» (destructive, красная). Тумблер до подтверждения остаётся во включённом положении.
- [ ] AC2. N — число открытых paper-сделок в БД (`paper_trades` без `closed_at`), M — число демо-позиций зеркала в
  активных статусах (`demo_mirror_orders`, `ACTIVE_MIRROR_STATUSES`). Числа запрашиваются при открытии модалки
  (свежие, не из кэша); пока грузятся — «Считаю открытые сделки…», кнопка «Выключить» доступна. Ошибка подсчёта —
  текст без чисел («Открытые paper-сделки и демо-позиции перестанут проверяться…») и выключить всё равно можно.
- [ ] AC3. «Отмена», крестик, Esc или клик мимо — движок не меняется, запроса на переключение нет.
- [ ] AC4. «Выключить» → движок выключен (тумблер в положении «выкл»), модалка закрывается. Во время запроса кнопки
  неактивны, текст «Выполняю…»; ошибка сервера — красный текст в модалке, тумблер остаётся включённым.
- [ ] AC5. Клик по выключенному тумблеру открывает модалку «Включить автоторговлю?» (короткий текст: движок начнёт
  тикать раз в минуту, пропущенные выходы догонятся по 1m-свечам) с кнопками «Отмена» и «Включить» (обычная, не
  красная). «Включить» — один клик, движок включается.
- [ ] AC6. Тумблер «Автоторговля» с теми же модалками есть в двух местах: в шапке (как сейчас) и в `/settings` в
  разделе «Paper — симуляция» (над карточками эпохи и бюджета, с пояснением, что он делает). Оба показывают одно и
  то же состояние: переключили в одном — второй обновился.
- [ ] AC7. Каждое переключение через UI пишет в журнал `/logs` запись события `engine.toggle` (уровень info):
  сообщение «Автоторговля выключена/включена», в данных — `enabled`, `by` (логин GitHub из сессии; без входа —
  `null`, в сообщении «вход выключен»), `source: "ui"`, при выключении — `openPaper` и `openDemo`.
- [ ] AC8. Если Telegram настроен (`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`), после переключения в чат уходит
  сообщение: «⏸ Автоторговля выключена в HH:MM UTC (<кто>). Открыто N paper-сделок и M демо-позиций — стопы и тейки
  не проверяются до включения.» / «▶️ Автоторговля включена в HH:MM UTC (<кто>).» Время — UTC, формат 24 ч.
- [ ] AC9. Telegram не настроен — переключение работает как обычно, сообщение не отправляется, ошибок нет. Telegram
  ответил ошибкой — переключение всё равно успешно, в журнал — warn `engine.toggle.notify` с текстом ошибки.

## Вне scope
- Логика движка при выключении (тик, догон выходов, зеркало) не меняется.
- Напоминание в Telegram «автоторговля выключена дольше часа» — не делаем сейчас (решение пользователя 2026-10-16).
- Демо-зеркало и задача 0012 (её worktree `binance-dashboard_0012-mirror-entry-fixes`) не трогаем; `mirrorDb.ts`
  только читаем (константы статусов).
- Подтверждение тумблеров отдельных экспериментов и галочки «Демо-счёт».

## Технические заметки
- Затронутые FSD-слайсы: `features/engine-toggle` (модалки, мутация), `entities/experiment` (схема/запрос числа
  открытых позиций), `pages/settings` (новое место тумблера), `app/server/experimentEngine.ts` и
  `app/api/experiments/engine/route.ts` (кто переключил, журнал, Telegram).
- Числа: отдельный лёгкий GET (например, `/api/experiments/engine/exposure` → `{ openPaper, openDemo }`), чтобы не
  считать их при каждом опросе статуса (раз в минуту). Тот же подсчёт — для сообщения при выключении на сервере.
- «Кто»: логин из сессии Auth.js (`nextAuth?.auth()`); без настроенного входа (локально) — `null`.
- Telegram: `getTelegramConfig()` + `sendTelegramMessage` из `shared/api/telegram`; отправка не блокирует ответ
  тумблера дольше таймаута клиента (10 с) и не роняет его.
- Код Edge Function `engine-tick` не меняется → этап выкатки `edge` не нужен (проверить граф импортов).
- Текст на `/experiments` «Включите «Автоторговлю» в шапке» — дополнить «или в /settings».
