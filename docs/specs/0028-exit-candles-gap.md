# 0028 · Выходы paper-движка теряют 1m-свечи после простоя движка

- **Тип:** bug
- **Статус:** approved
- **Серьёзность:** major
- **Дата:** 2026-10-15

## Шаги воспроизведения
1. У эксперимента есть открытая paper-сделка, `paper_trades.checked_until` = T.
2. Движок не тикает дольше 1000 минут (~16,7 ч): выключен тумблер «Автоторговля», упал раннер (VM / Edge Function),
   нет сети до Binance.
3. За время простоя цена задевает стоп (или тейк) сделки и возвращается.
4. Движок снова тикает.

## Ожидаемое поведение
Тик читает все закрытые 1m-свечи от `checked_until` до текущей минуты и закрывает сделку по стопу (тейку, трейлингу,
безубытку, тайм-стопу) по той свече, где уровень был задет, — как если бы простоя не было. `extreme` (MFE)
учитывает всю пропущенную часть.

## Фактическое поведение
`runTick` (`src/features/paper-engine/model/runTick.ts`, этап «1. Выходы») запрашивает
`deps.candles(market, symbol, "1m", count)` — **последние** `count` свечей, где
`count = min(ENGINE.maxMinuteCandles = 1000, (now − from)/1 мин + 1)`, без `startTime`. При разрыве > 1000 минут
свечи с `checked_until` до `now − 1000 мин` не запрашиваются никогда, а `walkExits` (`packages/trading-core/src/exits.ts`)
сдвигает `checkedUntil` на последнюю прочитанную свечу — пропущенный стоп/тейк теряется навсегда, сделка остаётся
открытой или закрывается позже по другой цене, `extreme` занижен. Ошибки в журнале нет. Путь общий для раннера VM и
Edge Function `engine-tick` (`src/app/server/engineTick.ts` → `buildTickDeps`).

## Причина
Заполняет Developer после диагностики: где и почему.

## Критерии приёмки
- [ ] AC1. Свечи выходов запрашиваются от `checked_until` (параметр `startTime` у `deps.candles` и у
  `fetchKlines` публичного API Binance), при разрыве больше лимита одного запроса — несколькими страницами подряд до
  текущей минуты; незакрытая свеча по-прежнему отбрасывается.
- [ ] AC2. Тест `runTick` (или `walkExits` + загрузчик): сделка со стопом, простой 1500 минут, стоп задет на 300-й
  минуте простоя и цена вернулась → сделка закрыта по `sl` с `closedAt` той свечи и ценой стопа. Тест падает до фикса.
- [ ] AC3. Тест: при разрыве ≤ 1000 минут число запросов свечей не растёт (одна страница, как сейчас).
- [ ] AC4. Ограничение веса API: разрыв дольше разумного предела (например, 7 дней) не дочитывается «в бесконечность»
  за один тик — тик дочитывает ограниченное число страниц, двигает `checked_until` только по прочитанному и
  продолжает на следующем тике; в журнал — `warn` с символом и размером разрыва.
- [ ] AC5. Комментарий о чтении 1m-свечей в коде движка соответствует новому поведению; README движка
  (`src/features/paper-engine/README.md`) — абзац о догрузке после простоя.
- [ ] AC6. Раннер VM и Edge Function `engine-tick` собираются и тикают (`pnpm check`, сборка функции).

## Вне scope
- Пересчёт уже закрытых сделок прошлых простоев (в эпохе 1 простоя > 16,7 ч не было — входы есть во всех часах).
- Свечи входов по таймфреймам эксперимента (там нужен только хвост, разрыв не теряет сигналов задним числом).
- COIN-M (`dapi`): если задача 0023 влита раньше — тот же `startTime` для `dapi`; если позже — она подхватывает
  параметр при слиянии.
