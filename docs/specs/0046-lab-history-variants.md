# 0046 · Лаборатория: вся история, причина выключения и варианты эксперимента

- **Тип:** feature
- **Статус:** approved
- **Раздел PRD:** §3.4 Авто-бот → «Лаборатория: вся история, причины выключения и варианты»
- **Дата:** 2026-10-16

## Цель
После старта эпохи 2 таблицы лаборатории показывают только текущую эпоху, а выключенные эксперименты просто
затемнены — непонятно, почему их выключили и как они шли раньше. Нужно: (1) смотреть статистику любого эксперимента и
таблиц за все эпохи сразу; (2) видеть причину выключения; (3) видеть, какие эксперименты — варианты другого
(контрольного), что в них изменено и как они идут рядом с контрольным (A/B), а не терять контрольный при проверке
новых настроек.

## Решения пользователя (2026-10-16)
- «Все эпохи» — пункт в выборе эпохи на `/stats`, `/experiments` и `/experiments/[id]`; по умолчанию — текущая эпоха;
  выбор — в URL.
- Причина выключения обязательна: категория + короткий текст + дата. `lab:apply` без причины не выключает, в
  `/settings` при выключении — окно с причиной. Уже выключенным причины заполняются из журнала лаборатории (запись в
  прод — после утверждения этого ТЗ).
- Варианты стоят строками под своим контрольным, сворачиваются; на странице эксперимента — «что изменено» текстом,
  автоматическое сравнение настроек (было → стало) и результаты контрольного и вариантов рядом. id не меняются.
- Правило лаборатории: новые настройки проверяются только вариантами рядом с работающим контрольным; вариант хуже
  контрольного выключается; контрольный, у которого идут варианты, выключается только с явного согласия
  пользователя и с причиной.

## Сценарии
1. Пользователь открывает `/experiments` → в выборе эпохи «Эпоха №2 (текущая)», «Эпоха №1», «Все эпохи» → выбирает
   «Все эпохи» → у каждого эксперимента сделки, PnL, win rate и прочие колонки — за всё время с первой эпохи;
   выключенные тоже видны со своей историей.
2. На `/stats` и на странице эксперимента — тот же выбор; на странице эксперимента в «Все эпохи» кривая капитала
   склеена через эпохи с отметками начала каждой эпохи, в списке сделок — сделки всех эпох с номером эпохи.
3. Выключенный эксперимент в `/experiments` → бейдж «выключен · убыточный»; наведение/тап → текст причины и дата.
   На странице эксперимента — та же причина в шапке.
4. В `/settings` пользователь выключает эксперимент → окно: категория (обязательно), текст (до 200 символов) →
   «Выключить». Если у эксперимента есть включённые варианты — в окне предупреждение «это контрольный для F97, PS99 —
   без него варианты не с чем сравнивать» и галочка «Да, выключить контрольный»; без неё кнопка неактивна.
5. Разбор лаборатории выключает эксперимент: `pnpm lab:apply --disable F96 --reason F96=loser --note "F96=<текст>"`;
   без `--reason` для выключаемого id — ошибка до записи. Повтор для уже выключенного — обновляет причину.
6. В `/experiments` под строкой F96 (контрольный) — строки его вариантов «↳ F97 · вариант A · цель 3R вместо 2R»,
   «↳ PS99 · вариант B · то же на spot»; шеврон у F96 сворачивает их.
7. Страница варианта → блок «Вариант A от F96»: ссылка на контрольный, «что изменено», таблица «настройка · у F96 ·
   у варианта» (только отличия), и сравнение «F96 / вариант»: сделки, win rate, средний R, PnL, profit factor за
   выбранную эпоху. Страница контрольного → блок «Варианты» со списком вариантов и теми же метриками.

## Критерии приёмки
- [ ] AC1. **Данные.** Миграция Drizzle (идемпотентная): `experiments.parent_id` (text, null), `variant_note`
  (text, null), `disabled_reason` (text, null), `disabled_note` (text, null), `disabled_at` (timestamptz, null).
  `experimentSchema` (`trading-core`) получает необязательные `parentId`, `variantNote`; `seedExperiments` /
  `pnpm lab:private` пишут их при вставке и обновлении (как `name`/`config`). Категории причины — константа
  `DISABLE_REASONS`: `loser` «убыточный», `worse-than-control` «хуже контрольного», `duplicate` «дубль»,
  `random-like` «не лучше случайного входа», `no-edge` «нет перевеса до комиссий», `costs` «съедают комиссии»,
  `manual` «вручную / другое». Включение эксперимента очищает поля причины. Вариант — один уровень: у контрольного
  нет `parent_id`; `lab:private` отклоняет файл, где родитель не существует или сам является вариантом.
- [ ] AC2. **«Все эпохи» на `/stats`.** В выборе эпохи есть «Все эпохи» (`?run=all`); total и группы считаются по
  сделкам всех эпох; фильтры и периоды 24 ч / 7 дней работают и в этом режиме; монеты в фильтре — из всех эпох.
- [ ] AC3. **«Все эпохи» на `/experiments`.** Появился выбор эпохи (текущая, каждая прошлая, «Все эпохи»; `?run=`);
  по умолчанию — текущая, как сейчас. В «Все эпохи» paper-колонки считаются по всем сделкам эксперимента (отдельные
  сбросы эксперимента и группы не отсекают историю), демо-колонки — по всем демо-зеркалам. Подпись под таблицей
  говорит, какой период показан. В прошлой эпохе — её сделки; тумблеры и галочка «Демо-счёт» работают в любом режиме.
- [ ] AC4. **«Все эпохи» на странице эксперимента.** Тот же выбор; статистика, кривая капитала (склеена, отметки
  начала эпох) и сделки (с колонкой «Эпоха») — за выбранный период. Процент и просадка — от текущего бюджета
  эксперимента; это сказано в подсказке (бюджет прошлых эпох не хранится — PRD «Открытые вопросы»).
- [ ] AC5. **Причина в интерфейсе.** У выключенного эксперимента в `/experiments`, `/settings` и на его странице —
  бейдж «выключен · <категория>», по наведению (на телефоне — по тапу) — текст и дата. Без причины (старые строки до
  backfill) — просто «выключен», как сейчас.
- [ ] AC6. **Выключение в `/settings`.** Выключение тумблером открывает окно с выбором категории (обязательно) и
  текстом; отмена оставляет эксперимент включённым. API `POST /api/experiments/settings/enabled` без категории при
  `enabled: false` → 400. Контрольный с включёнными вариантами: предупреждение со списком вариантов и обязательная
  галочка; API без `confirmControl: true` → 409 с тем же списком. Включение — без окна.
- [ ] AC7. **`lab:apply`.** `--reason <id>=<категория>` и `--note <id>=<текст>`; выключение без причины — ошибка до
  записи; неизвестная категория — ошибка со списком; уже выключенный + причина — обновление причины (строка «причина»
  в `apply.md`); выключение контрольного с включёнными вариантами — ошибка без `--force-control`. Тесты
  `scripts/lib/labApply.test.ts`.
- [ ] AC8. **Варианты в `/experiments`.** Варианты стоят под контрольным с отступом и подписью «вариант A/B/C… ·
  <что изменено>» (буква — по порядку id среди вариантов одного контрольного); шеврон у контрольного сворачивает и
  разворачивает их (по умолчанию развёрнуто, состояние — в localStorage). Сортировка таблицы упорядочивает группы по
  строке контрольного, варианты внутри группы — тем же столбцом. Вариант другой группы активов (spot под usdm) — тоже
  под контрольным, AG видно в своей колонке. Вариант, контрольного которого нет в списке, — обычной строкой.
- [ ] AC9. **Сравнение на странице эксперимента.** У варианта — блок «Вариант X от <контрольный>»: ссылка, «что
  изменено», таблица отличий настроек (`config`, `market`) «настройка · контрольный · вариант» по чистой функции
  `diffExperimentConfig` (тесты: вложенные поля, массивы, добавленные/удалённые ключи, без отличий — «настройки
  совпадают»), метрики рядом за выбранную эпоху. У контрольного — блок «Варианты» со списком и метриками.
- [ ] AC10. **Правило лаборатории.** Скилл `trading-lab` и агент `quant`: новые настройки — только вариантом с
  `parentId` и `variantNote`; контрольный не выключается, пока у него идут варианты (только с согласия пользователя);
  каждое выключение — с категорией причины. Шаблон `apply` в `/flow lab` и README `private/` (поля `parentId`,
  `variantNote`).
- [ ] AC11. **Пустые и ошибки.** Эксперимент без сделок в «Все эпохи» — нули, как сейчас; `?run=` с несуществующей
  эпохой — сообщение «эпохи нет» и выбор текущей; старые сделки без контекста не ломают страницы.
- [ ] AC12. **Прод (после мержа и выкатки).** Уже выключенным экспериментам проставлены причины из журнала
  лаборатории (`pnpm lab:apply --reason …`), существующим приватным вариантам — `parentId`/`variantNote`
  (`private/experiments.json`, `pnpm lab:private --prod`); в `/experiments` на проде видны причины и группы
  вариантов.

## Вне scope
- Хранение бюджета прошлых эпох (`runs.initial_budget`) — остаётся открытым вопросом PRD.
- История переключений тумблера (журнал всех включений/выключений) — хранится только последнее выключение.
- Варианты второго уровня (вариант варианта).
- «Все эпохи» в `pnpm lab:report` (там уже есть `--run`).
- Переименование id экспериментов.

## Технические заметки
- Затронутые слайсы: `entities/experiment` (db.ts, settings.ts, statsView.ts, view.ts, readModel.ts, settingsDb.ts,
  mirrorDb.ts, новый `lib/configDiff.ts`), `pages/experiments`, `pages/experiment-detail`, `pages/stats`,
  `pages/settings`, `src/app/server/experimentSettings.ts`, `app/api/experiments/**`, `scripts/lab-apply.ts`,
  `scripts/lib/labApply.ts`, `scripts/lib/labPrivate.ts`, `packages/trading-core/src/experiment.ts`.
- «Все эпохи» = без `run_id` и без `countedTrade()`; одна выборка сделок эксперимента/всех, сортировка по `opened_at`.
  Объём: десятки тысяч строк — пока приемлемо; при росте — агрегат в SQL.
- `run` в query: `number | "all"` (Zod), нужен и для `/api/experiments` и `/api/experiments/[id]`.
- Edge Function `engine-tick` импортирует `entities/experiment/model/*` (`npx madge`): новые колонки в `db.ts` не
  должны менять движок; миграция — до деплоя. Проверить `pnpm check:edge`.
- В spec, тестах и PR — только фиктивные id (F96, F97, PS99) и без реальных параметров (spec 0015). Причины и связи
  реальных экспериментов пишутся только в БД и `private/`.
