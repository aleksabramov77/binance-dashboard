# 0030 · Контекст входа, MAE и отсечённые сигналы в paper-сделках; отчёт лаборатории по эпохам и издержкам

- **Тип:** feature
- **Статус:** testing
- **Раздел PRD:** §3.4 Лаборатория; «5a. Очередь задач», строка 3
- **Дата:** 2026-10-15

## Цель
Разбор лаборатории отвечает не только «сколько заработал эксперимент», но и «в каких условиях рынка он зарабатывает»:
каждая paper-сделка хранит снимок рынка на момент входа и худшую цену внутри сделки (MAE), движок записывает сигналы,
которые не стали сделками из-за лимита позиций, а `pnpm lab:report` умеет прошлые эпохи и показывает издержки.

## Решения пользователя (2026-10-15)
- Свечи как архив не храним: история Binance неизменна и догружается по требованию; храним только то, что потом не
  восстановить (состояние на входе, отсечённые сигналы, MAE).
- Очередь до эпохи 2 ведёт сессия лаборатории, ТЗ и приёмку проходит сама, мерж — после тестов, ревью и CI.
- Параметры и результаты приватных экспериментов — только в `private/` (spec 0015); в тестах и spec — фиктивные (PS99).

## Сценарии
1. Движок открывает paper-сделку → в ней сохраняется `entry_context`: ATR% (ATR/цена), ADX(14), ширина Bollinger(20,2)
   в %, RSI(14), объём свечи / SMA20 объёма, расстояние до EMA200 в %, изменение за 24 ч, ранг символа в юниверсе
   эксперимента, режим BTC (выше/ниже EMA200 на 4h, ADX(14) 4h, изменение BTC за 24 ч), funding (futures), час UTC и
   день недели. Всё — по закрытой свече сигнала таймфрейма эксперимента (без заглядывания вперёд).
2. На каждом тике выходов вместе с `extreme` обновляется `mae` — худшая цена с момента входа (как `extreme`, только в
   другую сторону; свеча выхода учитывается).
3. Сигнал есть, но сделка не открыта (лимит `maxOpen`, символ уже в позиции у эксперимента, нет бюджета) → запись в
   журнал отсечённых сигналов: эксперимент, символ, направление, время свечи, причина, цена входа/стоп/тейк, которые
   были бы. Объём ограничен: хранение N дней и/или ограничение строк на эпоху (учесть `features/db-space`).
4. `pnpm lab:report --run <id>` → отчёт по прошлой эпохе (сейчас — только текущая, `readLabDataset` → `currentRun`).
5. `pnpm lab:report` → в сводке столбцы «R до издержек» и «издержки, R»; разрезы по корзинам контекста (режим BTC,
   ADX, ATR%, ширина BB, час UTC, funding — знак); MAE; «что было через 4/12/24 свечи ТФ после выхода» (по klines с
   публичного API по требованию, без хранения); число отсечённых сигналов по эксперименту и их гипотетический
   исход, если легко посчитать; контроль spot — честное сравнение «к случайному входу» (не против одного хвостового
   контроля: например, медиана контролей рынка или доходность рынка за период).

## Критерии приёмки
- [ ] AC1. Миграция Drizzle: `paper_trades.entry_context` (jsonb, по умолчанию `{}`), `paper_trades.mae` (double,
  nullable для старых строк); таблица отсечённых сигналов с индексом по (run, experiment); миграция идемпотентна на
  данных прод-формата. Схемы — в `src/entities/experiment/model/db.ts`.
- [ ] AC2. Чистая функция расчёта контекста (в `trading-core` или `features/paper-engine/lib`) с тестами на
  синтетических свечах: каждое поле, отсутствие заглядывания вперёд, поведение при нехватке истории (поле `null`).
- [ ] AC3. `walkExits` (`packages/trading-core/src/exits.ts`) ведёт `mae` для long и short; тесты; движок сохраняет
  `mae` вместе с `extreme`.
- [ ] AC4. Движок пишет отсечённые сигналы с причиной; объём ограничен (тест на лимит); раннер VM и Edge Function
  `engine-tick` собираются (`pnpm check:edge`).
- [ ] AC5. `lab:report`: `--run <id>`, столбцы издержек, разрезы по контексту, MAE, «после выхода», отсечённые
  сигналы, честный контроль spot; `report.json` содержит новые поля с описанием в `legend`; тесты
  `scripts/lib/labReport.test.ts`.
- [ ] AC6. Старые сделки без контекста не ломают отчёт и страницы `/experiments`, `/experiments/[id]`, `/stats`.
- [ ] AC7. Скилл `trading-lab` (`references/metrics.md`, `failure-modes.md`) и агент `quant` знают о новых полях
  (как читать MAE, контекст, отсечённые сигналы); README движка.
