# 0040 · `pnpm lab:apply` не принимает id приватных экспериментов

- **Тип:** bug
- **Статус:** done
- **Серьёзность:** major
- **Дата:** 2026-10-16

## Шаги воспроизведения
1. `pnpm -s lab:apply --disable PS99 --dry-run` (или любой id вида `PS..`, `PF..`, `PC..`).

## Ожидаемое поведение
Скрипт принимает id приватных экспериментов (spec 0015: `P` + буква группы `S`/`F`/`C` + номер) так же, как id
каталога, и показывает план «было → стало».

## Фактическое поведение
Ошибка `--disable: «PS99» — не похоже на id эксперимента (S01…F20)`: проверка формата в `scripts/lib/labApply.ts`
допускает только `^[SF]\d{2}$`. Тумблеры приватных экспериментов приходится переключать вручную в `/settings`.

## Причина
`planApply` (`scripts/lib/labApply.ts`) проверял id своей регуляркой `^[SF]\d{2}$`, написанной до spec 0015 и не
обновлённой, когда появились приватные эксперименты: формат `P` + группа + номер был только в `lab:private`
(`PRIVATE_ID_PATTERN`). Фикс: `lab:apply` принимает id каталога или id по `PRIVATE_ID_PATTERN`, импортированному из
`scripts/lib/labPrivate.ts`, — второй копии формата нет; текст ошибки называет оба формата.

## Критерии приёмки
- [ ] AC1. `lab:apply` принимает id каталога (`S01`, `F20`) и приватные (`PS99`, `PF99`, `PC99`, `PF100`) во всех флагах
  (`--disable`, `--enable`, `--mirror-on`, `--mirror-off`); формат id — общий с `lab:private`
  (`scripts/lib/labPrivate.ts`, `PRIVATE_ID_PATTERN`), без второй копии регулярного выражения.
- [ ] AC2. Мусор (`X1`, `PZ01`, пустая строка) по-прежнему отклоняется понятной ошибкой с примером обоих форматов.
- [ ] AC3. Тест, который падал до фикса (`scripts/lib/labApply.test.ts`), и `--dry-run` на прод-БД с приватным id
  показывает план без записи.

## Вне scope
- Проверка, что id существует в БД (её уже делает план «было → стало»).
