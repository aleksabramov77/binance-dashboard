# 009 · Сортировка таблиц не восстанавливается при возврате на страницу

- **Тип:** bug
- **Статус:** approved
- **Серьёзность:** major
- **Дата:** 2026-10-15
- **Связано:** PR #40 — «последняя сортировка таблиц запоминается в localStorage» (решение пользователя 2026-10-11)

Требование пользователя (2026-10-15): «Для каждой таблицы на каждой странице должны храниться поле, по которому
сортировать, и направление сортировки. Хранение — в localStorage. Вернувшись на страницу, сортировка должна
подтянуться из LS». Запущено как `/feature`; хранение уже есть, поэтому по решению пользователя ведётся как `/bug`.

## Шаги воспроизведения
Прод, 2026-10-15:
1. Открыть `/experiments`, в заголовке «PnL» выбрать «По убыванию». Таблица — F11, F04, F10…, URL —
   `?sort=pnl&dir=desc`, в localStorage `binance-dashboard:sort:experiments` = `{"key":"pnl","dir":"desc"}`.
2. Через меню в шапке перейти на `/stats`.
3. Через меню вернуться на `/experiments`.

## Ожидаемое поведение
Таблица снова отсортирована по PnL по убыванию, URL — `?sort=pnl&dir=desc`, у «PnL» стрелка ↓.
Так для каждой таблицы с сортировкой на каждой странице: если в URL сортировки нет, колонка и направление
берутся из localStorage. URL по-прежнему главнее localStorage (решение 2026-10-11).

## Фактическое поведение
URL — `/experiments` без параметров, порядок по умолчанию (F01, F02, F03). Попытки восстановить нет: при
возврате не было ни одного `history.replaceState`. Ошибок в консоли и журнале нет.
После полной перезагрузки страницы (F5) сортировка восстанавливается — сломан только возврат внутри приложения.

Затронуты все таблицы, которые восстанавливают сортировку через `useRestoreSort`:

| Страница | Таблица | Ключ (`binance-dashboard:sort:<ключ>`) |
|---|---|---|
| `/experiments` | эксперименты | `experiments` |
| `/stats` | разрезы | `stats` |
| `/settings` | Paper-счета / демо-счета | `paperSort` / `demoSort` |
| `/experiments/<id>` | сделки эксперимента | `tradesSort` |
| `/portfolio` | активы | `holdingsSort` |
| `/earn` | предложения Earn | `offersSort` |
| `/signals` | рост / падение | `gainersSort` / `losersSort` |

## Причина
Найдена Analyst на проде, подтверждена тестом (Developer, 2026-10-15).

В `next.config.ts` включено `cacheComponents: true`. С ним Next 16 при уходе со страницы не размонтирует её,
а прячет в React `<Activity>` (до 3 маршрутов, `node_modules/next/dist/docs/01-app/02-guides/preserving-ui-state.md`).
На проде после перехода на `/stats` заголовок «Эксперименты» остаётся в DOM скрытым. При возврате эффекты
запускаются заново, а `useRef` сохраняет значение. `useRestoreSort` (`src/shared/lib/sort/sortStorage.ts`)
при первом запуске ставит `done.current = true` и при повторном показе страницы сразу выходит.

Хватает убрать флаг: nuqs 2.10.2 сверяет состояние с URL прямо в рендере, когда страница снова на своём пути
(`useQueryStates`: `onCommittedPathname` → `reconcile()`), поэтому к запуску эффекта после возврата `inUrl` уже
отражает URL без сортировки. Хук общий для всех таблиц: `/experiments` и `/stats` вызывают `useRestoreSort`
напрямую, остальные — через `useTableSort`.

Что изменено: в `useRestoreSort` убран флаг `done` — эффект применяет сохранённую сортировку при каждом показе
таблицы (монтирование и возврат из `<Activity>`), если в URL её нет. Повторный запуск эффекта в StrictMode (dev)
безвреден: применяется та же сортировка. Тест — `src/shared/lib/sort/useRestoreSort.test.tsx` (happy-dom +
Testing Library): показ → `<Activity mode="hidden">` → показ и StrictMode; до фикса оба падали.

## Критерии приёмки
- [ ] AC1. `/experiments`: «PnL» → «По убыванию» → через меню на `/stats` → через меню назад на `/experiments`:
  таблица отсортирована по PnL по убыванию, URL — `?sort=pnl&dir=desc`, у «PnL» стрелка ↓.
- [ ] AC2. Направление тоже сохраняется: `/experiments`, «Сделки» → «По возрастанию» → уйти через меню и вернуться:
  та же колонка, по возрастанию, стрелка ↑.
- [ ] AC3. Другие страницы — тот же сценарий (выбрать сортировку, уйти через меню, вернуться) возвращает сортировку:
  `/stats` (разрезы), `/settings` (Paper-счета), `/experiments/<id>` (сделки эксперимента).
- [ ] AC4. «Сбросить сортировку» → уйти через меню и вернуться: порядок по умолчанию, старая сортировка не возвращается.
- [ ] AC5. URL главнее: при сохранённой сортировке PnL ↓ открыть ссылку `/experiments?sort=trades` — показана
  сортировка из ссылки.
- [ ] AC6. Без регрессии: полная перезагрузка (F5) страницы без параметров по-прежнему подтягивает сортировку
  из localStorage.
- [ ] AC7. Есть тест, который падал до фикса и проходит после: восстановление срабатывает при каждом показе
  таблицы (показ → скрытие `<Activity mode="hidden">` → показ), а не только при первом монтировании.

## Вне scope
- Таблицы без сортировки (например, «Демо-сделки» на `/signals`).
- Синхронизация сортировки между браузерами и устройствами — только localStorage этого браузера.
- Запоминание фильтров (рынок Spot/Futures и т.п.) — только сортировка.
- Отключение `cacheComponents` / `<Activity>`: сохранение состояния страниц остаётся, чинится хук.

## Заметки для Developer
- Vitest сейчас в окружении `node`, DOM-библиотек нет. Для теста хука можно включить DOM на один файл
  (`// @vitest-environment …`) и добавить Testing Library — это стек проекта по умолчанию
  (Vitest + Testing Library); перед добавлением проверь, что пакеты актуальны.
