# 009 · Сортировка таблиц: только localStorage, своя у каждой таблицы

- **Тип:** bug (по ходу задачи требование изменено пользователем — см. «Решения пользователя»)
- **Статус:** in-progress
- **Серьёзность:** major
- **Дата:** 2026-10-15
- **Номер задачи:** 0009 (`docs/HISTORY.md`)
- **Связано:** PR #37 (сортировка по любой колонке), PR #40 (последняя сортировка в localStorage, решение 2026-10-11)

## Решения пользователя (2026-10-15)
1. Запрос: «Для каждой таблицы на каждой странице должны храниться поле, по которому сортировать, и направление
   сортировки. Хранение — в localStorage. Вернувшись на страницу, сортировка должна подтянуться из LS».
   Хранение уже было (PR #40), поэтому задача пошла как `/bug`.
2. После первого круга приёмки — **сортировка в адресной строке не нужна**: «зачем нам вообще этот параметр…
   пусть в localStorage хранится сортировка для каждой таблицы». Отменяет решение 2026-10-11 «сортировка в URL,
   localStorage — запасной вариант, URL главнее».
3. **У каждой таблицы — уникальное имя «маршрут + таблица на странице»**; если таблиц на странице несколько,
   у каждой своё имя.
4. **Страница эксперимента — одна сортировка на все эксперименты**, а не своя у каждого: «хочу, чтобы всегда,
   когда я открываю страницу эксперимента, была сортировка по дате — открывая любой эксперимент»; `/stats` —
   так же всегда открывается со своей сортировкой.

## Шаги воспроизведения (исходный баг)
Прод, 2026-10-15:
1. Открыть `/experiments`, в заголовке «PnL» выбрать «По убыванию». Таблица — F11, F04, F10…, URL —
   `?sort=pnl&dir=desc`, в localStorage `binance-dashboard:sort:experiments` = `{"key":"pnl","dir":"desc"}`.
2. Через меню в шапке перейти на `/stats`.
3. Через меню вернуться на `/experiments`.

Фактически: URL `/experiments` без параметров, порядок по умолчанию (F01, F02, F03); после F5 — восстанавливается.

## Ожидаемое поведение
- Сортировка каждой таблицы (колонка и направление) хранится **только в localStorage этого браузера** и в адресную
  строку не пишется. Таблица всегда показывает сохранённую сортировку: при первом открытии, при возврате через
  меню или «Назад», после F5, в новой вкладке.
- Ничего не сохранено — порядок по умолчанию, как сейчас (`/experiments` — по эксперименту ↑, `/stats` — PnL ↓,
  `/portfolio` — по сумме в $ ↓, остальные — исходный порядок данных).
- Одна таблица — одна сортировка во всём приложении: поменял сортировку сделок на одном эксперименте — все остальные
  эксперименты (в том числе страницы, которые Next держит скрытыми в `<Activity>`) показывают новую.
- Фильтры (рынок, период, разрез и т.п.) остаются в URL, как были, — меняется только сортировка.
- localStorage недоступен (приватный режим, запрет) — сортировка работает до перезагрузки, но не запоминается;
  страница не падает.

## Имена таблиц
Ключ в localStorage — `binance-dashboard:sort:<маршрут>:<таблица>`; маршрут — шаблон пути без конкретного id
(`experiments/[id]`), поэтому сортировка сделок общая для всех экспериментов. Имена уникальны: Developer заводит
их так, чтобы повтор имени ловил тест или проверка типов, а `shared` не узнавал бизнес-терминов
(`docs/ai/architecture.md` → «Домены и изоляция»).

| Страница | Таблица | Имя (`<маршрут>:<таблица>`) |
|---|---|---|
| `/experiments` | эксперименты | `experiments:list` |
| `/experiments/<id>` | сделки эксперимента — одна на все эксперименты | `experiments/[id]:trades` |
| `/stats` | разрезы | `stats:groups` |
| `/settings` | Paper-счета | `settings:paper` |
| `/settings` | демо-счета | `settings:demo` |
| `/portfolio` | активы | `portfolio:holdings` |
| `/earn` | предложения Earn | `earn:offers` |
| `/signals` | рост | `signals:gainers` |
| `/signals` | падение | `signals:losers` |

Старые ключи (`binance-dashboard:sort:experiments`, `…:paperSort` и т.п.) не переносим: сортировку один раз
выбрать заново.

## Причина
Найдена Analyst на проде, уточнена Developer и Tester (2026-10-15).

1. В `next.config.ts` включено `cacheComponents: true`. С ним Next 16 при уходе со страницы не размонтирует её,
   а прячет в React `<Activity>` (до 3 маршрутов, `node_modules/next/dist/docs/01-app/02-guides/preserving-ui-state.md`).
   При возврате эффекты запускаются заново, а `useRef` сохраняет значение. `useRestoreSort`
   (`src/shared/lib/sort/sortStorage.ts`) при первом запуске ставил `done.current = true` и при повторном показе
   сразу выходил. Круг 1: флаг убран.
2. Круг 1 приёмки (Tester): эффект теперь срабатывает, но сортировка всё равно не восстанавливается — запись в URL
   теряется. Восстановление шло записью в URL через nuqs прямо во время мягкой навигации Next; nuqs сбрасывает
   свою очередь обновлений URL (`resetQueues` → `queue.abort`), когда историю меняет не он, и ожидающая запись
   пропадает (хронология: `pushState` → +21 мс эффект ставит `sort=pnl&dir=desc` в очередь → +82 мс `queue.abort`,
   `replaceState` не вызывается). Ломается любая мягкая навигация: меню, «Назад», первый заход по ссылке меню;
   работает только полная загрузка. Юнит-тест с заглушкой `apply` этого не ловил.
3. Решение пользователя 2 убирает причину целиком: сортировка не пишется в URL, читается из localStorage
   при рендере.

Что изменено (круг 2, Developer):
- `src/shared/lib/sort`: хранилище с подпиской (`sortStorage.ts`: ключ `binance-dashboard:sort:<имя>`, разбор через Zod,
  запасная память, если localStorage недоступен или запись не удалась; событие `storage` из других вкладок) и
  `useTableSort(table, fallback?)` на `useSyncExternalStore` — все экземпляры таблицы читают одно значение, на сервере
  «ничего не сохранено». Экземпляр, скрытый в `<Activity>`, получает новое значение при показе: React при повторном
  подключении эффектов сверяет снимок хранилища и перерисовывает компонент.
- Имена таблиц — в их слайсах: `defineSortTable("<маршрут>:<таблица>", KEYS)`; тип требует двоеточие, а
  `sortTables.test.ts` проверяет по исходникам `src`, что имена заданы литералом и не повторяются.
- Убраны `useRestoreSort`, URL-вариант `useTableSort` и `sort`/`dir` из `useExperimentsView`/`useStatsView`;
  ключи колонок переехали к функциям сортировки (`sortExperiments.ts`, `sortGroups.ts`).

## Критерии приёмки
- [ ] AC1. Адрес не меняется: `/experiments` → «PnL» → «По убыванию» — URL остаётся `/experiments`; таблица
  отсортирована по PnL ↓, у «PnL» стрелка ↓. Фильтр рынка (Spot/Futures) по-прежнему попадает в URL.
- [ ] AC2. Возврат через меню: `/experiments` с PnL ↓ → через меню на `/stats` → через меню назад: PnL ↓.
  Направление тоже: «Сделки» → «По возрастанию» → уйти и вернуться — «Сделки» ↑. Так же «Назад» браузера.
- [ ] AC3. F5 и новая вкладка: сортировка таблицы та же, что выбрана последней.
- [ ] AC4. Одна сортировка на все эксперименты: на `/experiments/<id>` выбрать «Вход» → «По убыванию» → открыть
  другой эксперимент — там тоже «Вход» ↓; поменять на втором на «Выход» ↑ → вернуться к первому («Назад»
  или ссылкой) — у первого тоже «Выход» ↑.
- [ ] AC5. Таблицы независимы: на `/settings` Paper-счета и демо-счета сортируются отдельно, на `/signals` — рост
  и падение отдельно; сортировка `/experiments` не меняет `/stats` и наоборот.
- [ ] AC6. «Сбросить сортировку» → порядок по умолчанию; после возврата через меню и после F5 — тоже по умолчанию.
- [ ] AC7. Старые ссылки: `/experiments?sort=trades&dir=desc` и `/settings?paperSort=id` открываются без ошибок,
  параметры сортировки игнорируются, таблица — с сортировкой из localStorage.
- [ ] AC8. Тесты на новое поведение: хранилище (имя → ключ, чтение/запись/сброс, мусор в значении, недоступный
  localStorage) и хук сортировки — показ → `<Activity mode="hidden">` → показ, два экземпляра одной таблицы
  видят изменение сразу. Тест проверяет настоящий путь данных (без заглушек на то, что ломалось).

Приёмка: AC1–AC3, AC5–AC7 — на локальном сервере задачи. Где в локальной базе нет данных (сделки эксперимента
для AC4, разрезы `/stats`), оркестратор проверяет на проде после выкатки.

## Вне scope
- Таблицы без сортировки (например, «Демо-сделки» на `/signals`).
- Синхронизация сортировки между браузерами и устройствами — только localStorage этого браузера.
- Запоминание фильтров (рынок, период, разрез) — остаются в URL, как были.
- Перенос старых сохранённых сортировок в новые ключи.
- Отключение `cacheComponents` / `<Activity>`.

## Заметки для Developer
- Для DOM-тестов уже есть `happy-dom` + Testing Library (`// @vitest-environment happy-dom` в файле теста).
- Синхронизацию экземпляров удобно сделать через `useSyncExternalStore` над localStorage со своей подпиской
  (событие `storage` приходит только из других вкладок); на сервере — снимок «ничего не сохранено».
- `useRestoreSort`, `useTableSort` с параметрами URL и разбор `sort`/`dir` в `useExperimentsView`/`useStatsView`
  после перехода становятся не нужны — убрать, а не оставлять мёртвым кодом.
