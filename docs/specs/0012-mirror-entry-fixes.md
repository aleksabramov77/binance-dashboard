# 0012 · Демо-зеркало: входы без потерь и без позиций без стопа

- **Тип:** feature
- **Статус:** in-progress (PR 1 готов к мержу, PR 2 впереди)
- **Раздел PRD:** §3.4 Авто-бот → Demo-зеркало ([spec 008](008-demo-mirror.md)); §6 «одна позиция на монету» — закрывается
- **Дата:** 2026-10-15

## Цель
Демо-зеркало повторяет на demo.binance.com входы отмеченных экспериментов, но с 11 окт. до биржи дошли только 284 из
552: 209 пропущены правилом «одна позиция на монету», 44 отклонены, и 2 спот-позиции открылись без стопа. Нужно, чтобы
зеркало повторяло лабораторию без потерь по нашей вине и никогда не оставляло позицию без защиты.

## Решения пользователя (2026-10-15)
- Несколько зеркал на одну монету: **Hedge mode** на демо-фьючерсах (лонг и шорт по монете живут раздельно), у каждого
  зеркала свои TP/SL на свой объём. Лимита на число зеркал на монету нет (константа в `config/mirror.ts`).
- Стоп, который биржа не принимает: стоп подтягивается к границе фильтра; на споте вход и защита — одной составной
  заявкой (OTOCO/OTO); на фьючерсах, если стоп всё же не встал, позиция сразу закрывается по рынку.
- Два PR: PR 1 — пункты 1–3 (быстрые починки), PR 2 — несколько зеркал на монету.

## Сценарии
1. Эксперимент входит в BTCUSDT на фьючерсах на $50 → через 1–2 минуты на демо открыта позиция ≥ $50 с TP/SL.
2. Эксперимент входит в монету, которой нет на демо-фьючерсах (BTW, DOS, TRUTH, CHIP, PUMP…) → в колонке «Demo» —
   «пропущена: нет на демо», запроса на вход не было, в отказы не считается.
3. Спот-эксперимент без стопа (S18, buy & hold) покупает монету → на бирже есть стоп в пределах фильтра биржи. Если
   биржа не приняла стоп — покупки нет (спот) или позиция сразу закрыта (фьючерсы), статус «не открылась».
4. Два эксперимента входят в одну монету (в одну или в разные стороны) → на демо у каждого своя позиция и свои TP/SL;
   закрытие одной paper-сделки закрывает только её зеркало, ордера другого остаются.

## Критерии приёмки
PR 1:
- [ ] AC1. Вход BTCUSDT-фьючерс на $50 (шаг 0,0001) открывается: объём на бирже ≥ minNotional, в шагах заявки нет
  ошибки «Объём … меньше минимального».
- [ ] AC2. Вход по монете, которой нет на демо-рынке, — статус «пропущена» с причиной «нет на демо-фьючерсах»
  (или «на демо-споте»), без запроса на вход. 30 старых отказов этого типа перенесены в «пропуски».
- [ ] AC3. Страховочный стоп (сделка без стопа) и любой стоп за фильтром `PERCENT_PRICE_BY_SIDE` / `PERCENT_PRICE`
  подтягивается к границе фильтра с запасом; в шагах заявки — «Стоп подтянут к границе фильтра биржи».
- [ ] AC4. Спот: вход, TP и SL уходят одной заявкой OTOCO (без TP — OTO). Биржа отклонила заявку → монеты не куплены,
  статус «не открылась». Если демо не поддерживает OTOCO/OTO — после покупки стоп, при отказе — продажа по рынку.
- [ ] AC5. Фьючерсы: стоп не встал → позиция закрыта по рынку, статус «не открылась: стоп отклонён». Статусов
  «открыта без защиты» по причине отказа стопа нет.

PR 2:
- [ ] AC6. Два эксперимента входят в одну монету в одну сторону → обе позиции открыты, у каждой свои TP/SL на свой
  объём; пропусков «уже есть зеркальная позиция» нет.
- [ ] AC7. Лонг одного эксперимента и шорт другого по одной монете → на демо обе позиции (Hedge mode), каждая со своими
  TP/SL.
- [ ] AC8. Закрытие paper-сделки закрывает только её зеркало: снимаются только её ордера, закрывается только её объём;
  если её стоп/TP уже сработал на бирже — статус «закрыта» без лишних ордеров.
- [ ] AC9. «Сбросить Demo» и ручное закрытие работают при нескольких зеркалах на монету; «Демо-сделки» на /signals
  показывают каждую сделку отдельно.
- [ ] AC10. Фьючерсы: если биржа принимает стоп до входа (проверка на демо) — стоп ставится первым, и при его отказе
  вход не отправляется. Если не принимает — остаётся откат из AC5, результат проверки записан в журнал spec.
- [ ] AC11. Контроль: за 12 часов после деплоя PR 2 отказов < 5 % входов, пропусков «монета занята» — 0.

Ошибки: не удалось переключить Hedge mode (на счёте есть позиции) → вход «не открылся» с понятным текстом «закройте
демо-позиции (Сбросить всё Demo)», тревога в Telegram.

## Вне scope
- Монеты, которых нет на демо, на другой рынок не переносим.
- Лимит экспозиции на монету, live-счёт.
- Выключение F01, эпоха 2.
- Пропуски «вход старше 10 минут» (14 из 15 — день включения экспериментов).

## Технические заметки
- Слайсы: `features/execute-trade` (`validateTrade`, `placeTrade`, `closeDemoPosition`), `features/demo-mirror`
  (`planMirror`, `runMirror`, `config/mirror`), `entities/experiment` (`mirrorDb`, `model/mirror`, миграция),
  `shared/api/binance` (`demoTrading`: `toRules`, OTOCO/OTO, `positionSide`, Hedge mode), композиция
  `src/app/server/demoMirror.ts`.
- PR 1:
  - `validateTrade`: после `floorToStep` при нехватке объёма + один шаг (не больше `MAX_MIN_NOTIONAL_BUMP` и лимита).
  - `SymbolRules.priceBand` из `PERCENT_PRICE_BY_SIDE` / `PERCENT_PRICE`; подтяжка стопа с запасом 1 %.
  - `MirrorDeps.hasSymbol` — проверка до `claim`; справочник фьючерсов уже кэшируется на 10 минут.
  - Спот: `POST /api/v3/orderList/otoco` и `/oto`; вход — LIMIT IOC по цене +0,5 %, `pendingQuantity` за вычетом
    комиссии. Фьючерсы: откат через `demoFuturesReduceMarket`.
- PR 2:
  - миграция `demo_mirror_orders.protect_refs jsonb` (algoId / orderListId);
  - `POST /fapi/v1/positionSide/dual`; `positionSide` во всех фьючерсных заявках; TP/SL по `quantity`, а не
    `closePosition`; порядок «стоп → вход → тейк», если демо принимает стоп до позиции;
  - убрать «монета занята» (`planMirror`, `activeMirrorSymbols`), а проверку открытой позиции в `placeTrade` оставить
    только для ручных сделок;
  - `closeDemoPosition` по `protect_refs`.
- Данные (запрос к `demo_mirror_orders` 2026-10-15): 209 пропусков «монета занята» — фьючерсы 143 (57 встречных),
  спот 68; STRKUSDT 15, RSRUSDT 14, SUSDT 11, BTCUSDT 10.
- Риски:
  - поддержка OTOCO/OTO на demo-споте — проверить первым делом;
  - переключение Hedge mode только на пустом счёте — перед деплоем PR 2 «Сбросить всё Demo»;
  - `groupFills`/`markTrades` при нескольких входах по монете.
