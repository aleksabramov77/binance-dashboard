# 0036 · Вкладка со старой сборкой ломается после деплоя и поднимает ложную тревогу «client»

- **Тип:** bug
- **Статус:** approved
- **Серьёзность:** minor
- **Дата:** 2026-10-16

## Шаги воспроизведения
1. Открыть дашборд на сборке A.
2. Выкатить сборку B со сменой контракта API (как в 0023: группа `futures` → `usdm`, добавлена `coinm`), вкладку не
   обновлять.
3. Через ≤ 30 с шапка показывает ошибку бюджетов лаборатории, в `/logs` — `error client`, через 15 мин — тревога
   монитора в Telegram «Всплеск ошибок «client»».

## Ожидаемое поведение
- Вкладка со старой сборкой узнаёт о новой версии и предлагает обновиться (плашка «Вышла новая версия — Обновить»);
  сама страница не перезагружается — не теряется ввод в форме сделки.
- Ошибки такой вкладки видны в журнале, но не считаются ошибками прода и не поднимают тревогу.

## Фактическое поведение
Тревога 2026-10-16: «🟡 Всплеск ошибок «client»: 11 за 15 мин (обычно ~0.0)». Все записи — одна и та же ошибка Zod:
`markets[1]` и `markets[2]` не входят в `"spot"|"futures"`. В текущем коде такого enum у `markets` нет: сервер
отдаёт `/api/experiments/budgets` с `markets: [spot, usdm, coinm]` (spec 0023), а вкладка со сборкой до 0023
проверяет ответ старой схемой (`experimentBudgetsSchema`, опрос раз в 30 с) → ошибка запроса → `reportClientError`
→ `POST /api/logs` → `log.error("client")` → монитор считает всплеск.

## Причина
Заполняет Developer после диагностики: где и почему.

## Решение
1. Версия сборки — `deploymentId` в `next.config.ts` из `VERCEL_DEPLOYMENT_ID` (локально не задан). Next ставит
   `data-dpl-id` на `<html>` и сам делает полную перезагрузку при навигации после деплоя. Сервер берёт текущую
   версию из env (`src/shared/config/env.server.ts`), клиент — из `document.documentElement.dataset.dplId`
   (helper в `src/shared/lib`).
2. `GET /api/version` → `{ version }` (тонкий route с `withLogging(..., { quiet: true })`).
3. Клиентский хук версии (TanStack Query: раз в 5 мин и при фокусе вкладки) и плашка «Вышла новая версия —
   Обновить» в шапке; версия не задана (dev) — плашки нет.
4. `reportClientError` добавляет `version` (новое optional-поле `clientErrorSchema`). `POST /api/logs`: версия
   клиента задана и ≠ версии сервера → `log.warn("client.stale", …)` с обеими версиями вместо `error("client")`.
   Монитор считает только `level=error` — тревоги нет. Ошибки клиента текущей версии и без версии — как раньше.

## Критерии приёмки
- [ ] AC1. Ошибка клиента с версией ≠ версии сервера пишется как `warn client.stale` (с обеими версиями) и не
  попадает в счётчик всплесков монитора.
- [ ] AC2. Ошибка клиента текущей версии (и клиента без версии) по-прежнему `error client`.
- [ ] AC3. Когда `/api/version` отдаёт версию, отличную от версии страницы, в шапке видна плашка «Вышла новая
  версия», кнопка «Обновить» перезагружает страницу.
- [ ] AC4. Без `VERCEL_DEPLOYMENT_ID` (локально, dev) плашки нет, поведение прежнее.
- [ ] AC5. Есть тест, который падал до фикса и проходит после; `pnpm check` и `pnpm build` зелёные.

## Вне scope
- Vercel Skew Protection (маршрутизация старых клиентов на старый деплой).
- Совместимость старых клиентских схем с новыми данными.
