# 0032 · Бэктест экспериментов лаборатории по истории свечей

- **Тип:** feature
- **Статус:** approved
- **Раздел PRD:** §3.4 Лаборатория; «5a. Очередь задач», строка 4
- **Дата:** 2026-10-16

## Цель
Отсеивать варианты экспериментов до живой эпохи: прогнать конфиг на 90–180 днях истории Binance тем же кодом, что и
живой движок, и получить те же метрики, что `pnpm lab:report`, отдельно на обучающем и проверочном отрезках.

## Решения пользователя (2026-10-15)
- Свечи как архив в БД не храним: история Binance неизменна и догружается; для бэктеста — дисковый кэш вне git.
- Очередь до эпохи 2 ведёт сессия лаборатории; ТЗ и приёмку проходит сама, мерж — после тестов, ревью и CI.
- Приватные конфиги читаются из `private/experiments.json`, отчёты пишутся в `private/lab/backtests/`; в коде, тестах
  и spec — только фиктивные примеры (PS99).

## Сценарии
1. `pnpm lab:backtest --file private/experiments.json --ids PF01,PS02 --days 120` → загрузка истории (с кэшем),
   прогон, отчёт `report.md` + `report.json` + `trades.csv` в каталоге `--out` (по умолчанию
   `private/lab/backtests/<дата>-<ids-hash>/`), в шапке — период, юниверс, ограничения.
2. Без `--file` — эксперименты каталога (`catalog.ts`) по `--ids`, например контроль `S19,F19`.
3. `--split 0.66` → метрики отдельно на обучающей (первые 2/3) и проверочной части периода; сравнение «вариант против
   базы семейства» в одном прогоне (`--ids F10,PF07,PF08`).
4. Повторный запуск с тем же периодом не скачивает свечи заново (кэш `~/.cache/binance-dashboard/klines` или
   `data/klines/`, вне git).

## Критерии приёмки
- [ ] AC1. Бэктест — повтор `runTick` (`src/features/paper-engine/model/runTick.ts`) с `createMemoryStore`
  (`model/memoryStore.ts`) и историческими `TickDeps`: `candles` отдаёт только свечи, закрытые к моменту тика
  (`now`), `tickers` — оборот за 24 ч на момент тика по историческим свечам, `funding` — историческая ставка
  (`fundingRate` history) или 0 с пометкой. Свой код торговой логики не пишется — тест: на коротком синтетическом
  отрезке бэктест и прямые вызовы `runTick` дают одинаковые сделки.
- [ ] AC2. Нет заглядывания вперёд: тест, где будущая свеча «выгодна», а сделки до неё не меняются.
- [ ] AC3. Шаг тика — закрытие свечи ТФ эксперимента; выходы — по свечам точнее ТФ: 1m для периода ≤ 30 дней и
  юниверса ≤ 10 символов, иначе 5m (или 15m) как приближение — выбранная точность пишется в шапку отчёта и
  report.json; влияние приближения показано тестом на синтетике (стоп и тейк в одной свече — засчитывается стоп).
- [ ] AC4. Юниверс: `majors` и `symbols` — как есть; `top`/`movers` — по историческому обороту на момент тика среди
  символов, которые торгуются сейчас (смещение выживших — в шапке отчёта). Не-крипто и стейблкоины исключены, как в
  движке (0029).
- [ ] AC5. Метрики и отчёт — через `buildLabReport`/`renderLabReport` (`scripts/lib/labReport.ts`): сводка, семейства,
  разрезы, MAE, контекст входа (0030), `--split` — две таблицы и разница; контроль (`random`) в том же прогоне.
- [ ] AC6. Загрузка: публичный API Binance с соблюдением веса (лимитер, ретраи на 429/418 с паузой), кэш на диске
  по (рынок, символ, интервал, месяц); `--no-download` — только из кэша. Прогресс в консоли.
- [ ] AC7. Тесты: синтетические свечи, без сети. README модуля, раздел в скилле `trading-lab` (как читать бэктест,
  чем он не является: оптимистичное исполнение, выжившие, funding), `.config/flows/lab.yaml` — бэктест кандидатов на
  этапе ideate.

## Вне scope
- Оптимизация параметров перебором (grid search) — только прогон заданных конфигов.
- Хранение результатов в БД и UI.
- Демо-зеркало.

## Технические заметки
- `runTick` уже принимает `now` и все внешние зависимости через `TickDeps`; `memoryStore` — для тестов и прогонов без
  БД; `candles` поддерживает `startTime` (0028).
- Объём: 120 дней × 1h × 30 символов ≈ 86 тыс. свечей — несколько десятков запросов; 1m за 120 дней на символ — 173
  запроса по 1000 — отсюда приближение выходов в AC3.
