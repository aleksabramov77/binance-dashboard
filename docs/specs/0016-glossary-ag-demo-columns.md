# 0016 · Глоссарий и справка, группа активов (AG) и демо-метрики в таблице экспериментов

- **Тип:** feature (задача A из четырёх: A — эта, B — остатки Paper | Demo | Real в хедере и сбросы, C — статистика по счетам, D — группа COIN-M в Paper и зеркале)
- **Статус:** testing
- **Раздел PRD:** §3.4 Авто-бот → Лаборатория экспериментов; §2 Разделы приложения (новая страница `/help`)
- **Дата:** 2026-10-15

## Цель
Статистика стратегий собирается на трёх счетах — Paper (симуляция), Demo (Binance Demo Trading) и позже Real — и
в трёх группах активов Binance (Spot, USDⓈ-M, COIN-M) с разными наборами инструментов. Приложение должно говорить
на одном языке с пользователем и с AI-документацией: один глоссарий как источник истины, видимая группа активов у
каждого эксперимента, те же метрики для демо-сделок, что и для paper, и быстрый переход от «отказов и пропусков»
зеркала к их причинам в журнале.

## Решения пользователя (2026-10-15)
- Требование из 9 пунктов разбито на 4 задачи подряд; COIN-M в движке — отдельная задача D после остальных.
- «Группа активов» — **AG** (Asset Group). Коды групп: **`SPOT`**, **`FT:USDM`** (USDⓈ-M фьючерсы), **`FT:COINM`**
  (COIN-M фьючерсы). В коде и БД внутренние значения `market` остаются `spot` / `futures` (переименование в
  `usdm` и добавление `coinm` — задача D), в UI и документации — коды и названия из глоссария.
- Источник истины — markdown-документ для AI (`docs/ai/glossary.md`); страница справки `/help` рендерит его
  содержимое, а не дублирует его.
- Demo Equity эксперимента = его стартовый бюджет (`initial_budget`) + Σ PnL закрытых демо-сделок после
  демо-сброса (отдельного демо-капитала у эксперимента нет, демо-счёт общий).
- Цвет демо-колонок утверждает пользователь по скриншотам на этапе разработки.

## Ответы на вопросы исследования (п. 1 требования)
- **Spot** — спотовый демо-счёт: Binance выдаёт 5 000 USDC + 5 000 USDT (≈ $10 000); остальные монеты (LTC, ENA,
  NEAR, ZEC…) — остатки демо-сделок приложения; ≈ 9 903 USDT = 10 000 минус убытки и комиссии.
- **USDⓈ-M** — бессрочные фьючерсы с маржой в стейблах: 5 000 USDC + 5 000 USDT **+ 0,01 BTC** (BTC принимается
  как залог мультиактивной маржи). 0,01 BTC никто не покупал: баланс ровно 0.01000000, нереализованный PnL 0 — это
  стартовый набор, он выдаётся при создании счёта и при каждом «Сбросе». Поэтому ≈ 10 743 USDT.
- **COIN-M** — фьючерсы с маржой в самих монетах (контракты BTCUSD_PERP и т.п.): стартовая корзина ETH 0,5, BNB 1,5,
  BTC 0,01, NEAR 90, TRX 700, CHZ 5 000, UNI 30, LINK 15…; долларовая оценка (≈ 6 829 USDT) плавает вместе с курсами.
- Сброс баланса демо-счёта есть только в интерфейсе demo.binance.com; API-метода сброса нет
  (developers.binance.com → Demo Mode → General Info). Хост `demo-dapi.binance.com` (COIN-M) по API доступен.

## Сценарии
1. Пользователь открывает `/help` → видит глоссарий (разделы, термин, сокращение, код, описание) с поиском и
   ссылки на документацию проекта; тот же текст лежит в `docs/ai/glossary.md`, который читает AI.
2. Пользователь открывает `/experiments` → у каждой строки колонка «AG» с кодом группы (`SPOT`, `FT:USDM`), по ней
   можно сортировать, в меню заголовка — описание из глоссария.
3. В той же таблице у демо-сделок есть «Демо: Profit factor», «Демо: Max DD», «Демо: Equity», и все демо-колонки
   визуально отделены оттенком фона.
4. У строки «5 отказ · 29 пропуск» пользователь нажимает иконку → открывается `/logs` с фильтрами из URL: только
   события отказов и пропусков зеркала этого эксперимента за 14 дней; каждая запись раскрывается и показывает
   причину (нет на демо, вход старше 10 минут, объём ниже минимума, отказ биржи…).
5. На `/settings` диалог «Сбросить всё Demo» честно описывает, что произойдёт, и даёт ссылку на demo.binance.com,
   где баланс сбрасывается вручную.

## Критерии приёмки
- [ ] AC1. Файл `docs/ai/glossary.md` существует, включён в таблицу `docs/ai/README.md`; содержит разделы «Счета»
  (Paper, Demo, Real), «Группы активов» (AG; `SPOT`, `FT:USDM`, `FT:COINM` с наборами инструментов), «Лаборатория»
  (эксперимент, стратегия, эпоха/run, юниверс, бюджет, тик, движок, сброс), «Зеркало» (demo-зеркало, отказ,
  пропуск, статусы), «Метрики» (PnL, win rate, Profit factor, Max DD, Equity, R, комиссии), «Сигналы» (сетап, сигнал).
- [ ] AC2. `pnpm glossary` генерирует `src/pages/help/config/glossary.json` из markdown; повторный запуск не меняет
  файл; тест падает с подсказкой «запусти pnpm glossary», если JSON отстал от markdown; парсер покрыт тестами.
- [ ] AC3. Страница `/help` («Справка» в навигации): глоссарий по разделам, поиск по термину/сокращению/коду/описанию
  (без перезагрузки), блок «Документация» со ссылками на `docs/ai/README.md`, `docs/PRD.md`, `docs/ai/glossary.md`
  в GitHub. Новых npm-зависимостей нет.
- [ ] AC4. `/experiments`: колонка «AG» сразу после «Эксперимент» показывает код группы (`SPOT` / `FT:USDM`),
  сортируется, в меню заголовка — описание из глоссария; бейдж рынка в колонке «Эксперимент» убран. Фильтр
  «рынок» над таблицей использует те же названия групп.
- [ ] AC5. `/experiments`: колонки «Демо: Profit factor», «Демо: Max DD», «Демо: Equity» после «Демо: PnL», считаются
  по закрытым демо-сделкам после демо-сброса теми же формулами, что paper (PF = gross profit / gross loss, «∞» без
  убытков; Max DD — просадка от пика equity в %; Equity = стартовый бюджет + Σ PnL демо); без демо-сделок — «—».
  Сортировка по ним работает.
- [ ] AC6. Все колонки «Демо: …» (заголовки и ячейки) выделены единым оттенком фона, отличным от paper-колонок;
  вариант цвета выбран пользователем из 2–3 скриншотов в ходе разработки (выбор записан в журнале spec).
- [ ] AC7. Каждый отказ и пропуск зеркала пишется в журнал отдельной записью: `mirror.rejected` (warn) и
  `mirror.skipped` (info) с `experimentId`, `tradeId`, `symbol`, `market`, причиной; сводка `mirror.run` остаётся.
- [ ] AC8. `/logs` понимает URL-параметры `level`, `event` (список через запятую), `experiment`, `days` (1–14,
  по умолчанию 2) и показывает их в фильтрах над списком; `GET /api/logs` фильтрует по ним на сервере.
- [ ] AC9. У «N отказ · M пропуск» в `/experiments` и в таблице Demo на `/settings` есть иконка-ссылка на
  `/logs?level=info&event=mirror.rejected,mirror.skipped&experiment=<id>&days=14`; на странице логов видны только
  события этого эксперимента (записи, созданные до этой задачи, в журнале отсутствуют — это ожидаемо).
- [ ] AC10. Диалог «Сбросить всё Demo» на `/settings` не обещает сброс баланса на Binance; текст объясняет, что
  закрываются демо-позиции и обнуляется демо-статистика, и даёт ссылку «Сбросить баланс на demo.binance.com».
- [ ] AC11. Описание колонки «Max DD» на `/experiments` и `/stats` — «максимальная просадка от пика equity, %».
- [ ] AC12. Ошибки и пустые состояния: нет демо-сделок — демо-метрики «—»; `/logs` без совпадений — «Записей нет»
  с кнопкой «Сбросить фильтры»; битый `glossary.json` невозможен (тест AC2); `/help` без JS показывает список целиком.

## Технические заметки
- **Глоссарий.** `docs/ai/glossary.md`: заголовки `## Раздел`, таблицы `| Термин | Сокращение | Код | Описание |`.
  Чистый парсер `scripts/lib/glossary.ts` (+ `glossary.test.ts`, как `worktreePlan.ts`); CLI `scripts/glossary.ts`
  (`pnpm glossary`) пишет `src/pages/help/config/glossary.json`; тест `src/pages/help/config/glossary.test.ts`
  сверяет JSON с разбором md. Страница `src/pages/help` (платформа, как `pages/logs`), роут `app/help/page.tsx`,
  пункт в `src/shared/config/navigation.ts`. Ссылки на GitHub — константа репозитория в `shared/config`.
- **AG.** Метки и коды групп — одна карта в `entities/experiment/model` (`market → {code, label, description}`),
  используется колонкой «AG», фильтром, `MarketBudgets` и `/settings`; описание колонки берётся из `glossary.json`
  по коду термина `AG`.
- **Демо-метрики.** `entities/experiment/api/mirrorDb.ts → mirrorSummaries` дополнительно возвращает PnL закрытых
  демо-сделок в порядке закрытия; `entities/experiment/lib/stats.ts → computeDemoStats(pnls, initialBudget)`
  переиспользует `profitFactor`/`maxDrawdown` из `computeStats`; `demoSummarySchema` (`model/view.ts`) получает
  `profitFactor`, `grossProfit`, `maxDrawdownPct`, `equity`; `sortExperiments.ts` — новые ключи.
- **Журнал.** `src/app/server/demoMirror.ts` / `features/demo-mirror/model/runMirror.ts` — вызовы `log.warn/info`
  по каждому `rejected`/`skipped`; `src/app/server/logs.ts → readLogs` и `app/api/logs/route.ts` — параметры
  `event[]`, `experiment` (`data->>'experimentId'`), `days`; `src/pages/logs` — nuqs-ключи `event`, `experiment`,
  `days`, UI фильтров; `entities/experiment/ui/DemoMisses.tsx` — иконка-ссылка (`lucide-react`).
- **Правки текста.** `src/pages/settings/ui/DemoAccountsCard.tsx`, `src/pages/experiments/ui/ExperimentsPage.tsx`,
  `src/pages/stats/ui/StatsPage.tsx`.
- Документация: `docs/ai/README.md` (строка глоссария), `docs/ai/architecture.md` (платформа: `pages/help`, фильтры
  логов), PRD §2 и §3.4.
- Риски: журнал хранится 14 дней — ссылка показывает только свежие отказы; `experimentId` в `data` старых записей
  нет.
