# 002 · Автосделки по всем сигналам (демо) для сбора статистики

- **Тип:** feature
- **Статус:** done
- **Раздел PRD:** §3.4 «Авто-бот» → «Автосделки (демо)»
- **Дата:** 2026-10-10

## Цель
Набрать статистику по правилам сетапов на длинной дистанции (несколько часов, ночь): без ручных
кликов входить в каждый сигнал на Binance Demo и видеть итог — сколько закрыто в плюс/минус и PnL.

## Сценарии
1. Пользователь на `/signals` включает переключатель «Автосделки (демо)» → сервер сразу делает цикл
   и дальше каждые 2 минуты: скан → отбор → предпроверка → вход с TP/SL.
2. Вкладку можно закрыть: цикл живёт в процессе Next-сервера (`instrumentation.ts`), состояние
   переключателя — в `data/auto-trade.json` и переживает перезапуск.
3. На панели — последние решения (вход / пропуск / отказ / ошибка с причиной); над «Демо-сделками» —
   сводка: закрыто, в плюс/минус, % прибыльных, итог закрытых, открытые и их текущий PnL.

## Решения (2026-10-10)
Пользователь: «добавь переключатель принимать сделки автоматически, будем брать всё, на что приходят
сигналы»; «делай всё, потом мерж сам, включай авторежим». Остальное решено разработчиком
(пользователь спал), параметры — в `features/auto-trade/config/autoTrade.ts`:
- Берём **все** сетапы — и `ready`, и `watch` (статус пишется в решение, статистику можно разделить).
- Перед входом — та же предпроверка, что в окне сделки (`recheckSetup`): `stale` → пропуск, иначе
  свежие уровни; TP = TP1. Вход — через `placeTrade` (вся серверная валидация и лимиты).
- Размер: риск 1% кошелька рынка, объём ≤ $100, плечо 2x (как умолчания калькулятора).
- Без повторов: символ, по которому есть позиция/ордера, пропускается; ту же пару и сторону —
  не раньше чем через 2 ч после прошлого автовхода (id сетапа = `SYMBOL:direction`, без времени).
- Предохранители: ≤ 5 сделок за цикл, ≤ 20 символов в сделке одновременно (по отправленным сделкам);
  после отказа биржи / неактуальной предпроверки — пауза 30 мин; выключение посреди цикла
  останавливает следующие входы.

## Критерии приёмки
- [x] AC1. На `/signals` есть переключатель «Автосделки (демо)»; состояние читается с сервера и
  сохраняется в `data/auto-trade.json`.
- [x] AC2. Включение → в течение секунд цикл: на живом демо-счёте 2026-10-10 открыт шорт PIXELUSDT
  с TP и SL; MAGIC/KAIA/BAT/ATOM пропущены «по символу уже есть позиция или ордера».
- [x] AC3. Цикл идёт без открытой вкладки (сервер, таймер 2 мин); во время `next build` не стартует.
- [x] AC4. Решения видны на панели (8 последних), повторяющиеся пропуски не дублируются; в журнале —
  события `auto.toggle`, `auto.cycle`, `auto.trade`, `trade.*`.
- [x] AC5. Над «Демо-сделками» — сводка; таблица до 150 строк и обновляется раз в минуту.
- [x] AC6. Ошибки: демо не настроено / нет балансов → цикл пропущен, текст ошибки на панели;
  сбой одного сетапа не ломает остальные (тесты `runCycle.test.ts`).

## Вне scope
- Trailing stop, частичная фиксация, TP2; живая (не демо) торговля; отдельный экран бота.
- Метка «авто/вручную» в таблице сделок (решения автоторговли — на панели и в журнале).

## Технические заметки
- `features/auto-trade` (сервер): `planEntries`, `sizeAutoTrade` (чистые, тесты), `runAutoTradeCycle`
  (зависимости внедряются), `autoTrader` (таймер в `globalThis`: в dev instrumentation и роуты —
  разные бандлы), `stateStore` (атомарная запись JSON).
- Композиция фич — в слое app: `src/app/server/autoTrade.ts`; старт — корневой `instrumentation.ts`.
- `app/api/auto-trade` — GET состояние, POST `{ enabled }`.
- `features/auto-trade-toggle` (клиент) — панель; `widgets/trade-log/lib/summarizeTrades`.
- Нагрузка: цикл = скан (кэш 60 с) + обзор счёта + на каждый вход 3 запроса свечей/тикера и сделка.
