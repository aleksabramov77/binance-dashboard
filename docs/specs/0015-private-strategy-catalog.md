# 0015 · Приватные эксперименты и анализы лаборатории

- **Тип:** feature
- **Статус:** approved
- **Раздел PRD:** §3.4 Авто-бот → «Лаборатория экспериментов» → «Приватные эксперименты»
- **Дата:** 2026-10-15

## Цель
Репозиторий публичный: бесплатные безлимитные GitHub Actions и защита веток. Удачные находки лаборатории —
параметры экспериментов, гипотезы, отчёты и разборы — коммерческая тайна и в публичный git не попадают.
Принцип: **движок и строительные блоки стратегий — публичные, «рецепты» и результаты — приватные.**

## Решения пользователя (2026-10-15)
- Репозиторий `binance-dashboard` остаётся публичным.
- Приватные данные — в отдельном приватном репозитории `aleksabramov77/binance-dashboard-private`, клон которого
  лежит в игнорируемой папке `private/` проекта. Шифрование в публичном репо отклонено: шифротекст публичен
  навсегда (утечка ключа раскрывает всю историю, ротация не помогает), ключ нужен на каждой машине и в CI,
  диффы и ревью нечитаемы.
- Приватный эксперимент заводится JSON-описанием в `private/experiments.json` и командой `pnpm lab:private`
  (без формы в UI). Эксперименты придумывает и заводит Claude через `/flow lab`; пользователь утверждает.
- Анализы `/flow lab` (report, review, ideas) хранятся в `private/lab/` и пушатся в приватный репозиторий.

## Как это работает
- Движок и экраны уже читают эксперименты только из таблицы `experiments` (Supabase). Сид публичного каталога
  (`catalog.ts`) делает upsert только своих id и чужие строки не трогает — приватный эксперимент, записанный в БД,
  торгуется на VM и в Edge Function без изменений деплоя. Vercel, CI и Edge Function файлы `private/` не нужны.
- `private/experiments.json` — массив экспериментов в формате каталога (`experimentSchema` из `trading-core`):
  `id`, `market`, `name`, `hypothesis`, `config`; необязательные `initialBudget` (по умолчанию 10 000),
  `enabled` (по умолчанию `true`), `demoMirror` (по умолчанию `false`) — как у каталога, пишутся только при вставке.
- id приватного эксперимента: `P` + буква рынка + номер — `PS01` (spot), `PF01` (futures). Не пересекается с id
  каталога (`S..`, `F..`).

## Сценарии
1. Claude в `/flow lab` предлагает гипотезу → пользователь выбирает → Claude дописывает её в
   `private/experiments.json`, запускает `pnpm lab:private`, коммитит и пушит приватный репозиторий → эксперимент
   появляется в `/experiments` и начинает торговать на следующем тике.
2. Claude меняет параметры приватного эксперимента в JSON и снова запускает `pnpm lab:private` → в БД обновляются
   `name`, `hypothesis`, `config`; тумблеры, бюджет и сделки не трогаются.
3. Разбор `/flow lab` сохраняет `report.md`, `review.md`, `ideas.md` в `private/lab/<прогон>/` и пушит их.
4. Новый компьютер / новый worktree: `pnpm lab:private --clone` (или инструкция в README) клонирует приватный
   репозиторий в `private/`; worktree получает ссылку на `private/` основного checkout, как `.env.local`.

## Критерии приёмки
- [ ] AC1. `private/` в `.gitignore`: файл в `private/` не виден в `git status` публичного репозитория.
- [ ] AC2. `pnpm lab:private --dry-run` при корректном `private/experiments.json` печатает список экспериментов
  (id, рынок, название, «новый» / «обновится») и в БД ничего не пишет.
- [ ] AC3. `pnpm lab:private` записывает эксперименты в БД; после этого на локальном сервере worktree
  приватный `PS01` виден в `/experiments` с названием и гипотезой, как любой эксперимент каталога.
- [ ] AC4. Страница `/experiments/PS01` открывается и показывает гипотезу и описание конфига (id не из каталога).
- [ ] AC5. Повторный `pnpm lab:private` после правки `config` в JSON обновляет описание конфига в `/experiments/PS01`,
  а выключенный в `/settings` тумблер `PS01` остаётся выключенным.
- [ ] AC6. Ошибки: невалидный JSON, нарушение схемы, id без префикса `PS`/`PF` или не совпадающий с рынком,
  повтор id, совпадение с id каталога — команда завершается с ненулевым кодом, понятной ошибкой (какой эксперимент
  и какое поле) и ничего не пишет в БД. Нет файла `private/experiments.json` — подсказка, как клонировать приватный
  репозиторий.
- [ ] AC7. Команда печатает, в какую БД пишет (хост без пароля или «локальная PGlite»), до записи.
- [ ] AC8. Сид каталога на тике не удаляет и не меняет приватные строки (тест).
- [ ] AC9. В worktree, созданном `pnpm wt new`, есть `private/` основного checkout (ссылка), если он существует.
- [ ] AC10. Приватный репозиторий `aleksabramov77/binance-dashboard-private` создан (private), склонирован в
  `private/`, в нём `README.md` (что лежит и как пользоваться), `experiments.json` (пустой массив `[]`) и `lab/`.
- [ ] AC11. Документация: в `docs/ai/architecture.md` — раздел «Приватные эксперименты» (механизм, без содержимого);
  в `CLAUDE.md` и `docs/ai/conventions.md` — правило: параметры, гипотезы и результаты приватных экспериментов
  не писать в публичные файлы, spec, коммиты, описания PR и issue; новые эксперименты лаборатории — в
  `private/experiments.json`, не в `catalog.ts`.
- [ ] AC12. Если PR #47 (`/flow lab`, скилл `trading-lab`) влит до разработки: `lab.yaml` пишет report/review/ideas в
  `private/lab/<run-id>/` и пушит приватный репозиторий; этап `experiment` заводит эксперимент в
  `private/experiments.json` через `pnpm lab:private` (без публичной spec с параметрами). Не влит — отдельная задача,
  запись в «Открытых вопросах» PRD.

## Вне scope
- Форма создания и редактирования экспериментов в UI.
- Удаление приватного эксперимента из БД (выключение — тумблером в `/settings`, как сейчас).
- Перенос существующих 40 экспериментов каталога в приватные: они уже в публичной истории git, перенос ничего не скрывает.
- Переписывание истории git.
- Приватный код новых типов входа/выхода: новый строительный блок стратегии остаётся в публичном `trading-core`,
  приватны только его комбинации и параметры.

## Технические заметки
- Затронутые слайсы: `entities/experiment` (сид/upsert — переиспользовать `seedExperiments`), `features/paper-engine`
  (публичный каталог — для проверки пересечения id), `scripts/lab-private.ts` + чистая логика в `scripts/lib/`
  с тестами (как `scripts/lib/labReport.ts` в PR #47), `scripts/worktree.ts` (ссылка `private/`),
  `app/experiments/[id]/page.tsx` (динамические id вне каталога).
- БД — как у `pnpm db:migrate`: `DATABASE_URL` из `.env.local` (прод — Supabase), без неё — PGlite.
- Приватный репозиторий создаётся через `GH_CONFIG_DIR="$HOME/.config/gh-personal" gh repo create … --private`.
- Риск: агент по привычке скопирует параметры в публичную spec или PR — закрывается правилом AC11 и ревью.
