## 1. Концепция

Личный локальный дашборд для одного пользователя (владельца аккаунта Binance). Цель — видеть,
где лежат деньги и сколько они приносят, находить, где выгоднее их держать, а дальше —
находить краткосрочные торговые возможности и исполнять их в один клик с заранее
выставленными Take Profit / Stop Loss. В перспективе — автоматический бот на отдельном экране.

Принципы:
- **Личное приложение.** Не рабочее, не связано с SDG / Cupid Media. Репозиторий — приватный
  `aleksabramov77/binance-dashboard`.
- **Локально.** Работает на Mac пользователя (`pnpm dev`, порт 5000 или следующий свободный).
  Данные и ключи лежат только на этом компьютере.
- **Безопасность ключей.** Ключи хранятся только в `.env.local` (не в git), используются только сервером.
  Ключ для чтения и торговый ключ — разные. Права на вывод средств не выдаются никогда.
- **Честность рекомендаций.** Сигналы — это гипотезы, а не гарантия. Каждую рекомендацию сопровождают
  риск/прибыль и размер позиции, а её реальная точность отслеживается в журнале.
- **Стек.** Next.js (App Router) · TypeScript strict · TanStack Query · nuqs · Zod · Tailwind + shadcn/ui ·
  Biome · Vitest. Архитектура — Feature-Sliced Design (роутинг в `app/`, слои в `src/`).

## 3. Требования по разделам

### 3.1 Earn — где выгоднее держать деньги ✅
- Данные: все продукты Binance Simple Earn (Flexible + Locked, ~550 шт.) с публичного эндпоинта
  сайта, без ключа. Цены в USD берутся из `api/v3/ticker/price`.
- Пользователь вводит сумму в USD. Для неё считается **реальная средневзвешенная ставка** с учётом
  бонусных ступеней («+2% до 10 000 USDC, выше — базовая») и лимитов на пользователя.
- Топ-3 предложений и таблица. Фильтры: Flexible/Locked, монета, «только стейблкоины» (по умолчанию),
  «скрыть распроданные». Фильтры хранятся в URL.
- Лента «Что изменилось» между снимками: новые и убранные продукты, смена ступеней,
  распродано/снова доступно, сдвиг ставки ≥ 0,5 п.п.
- Снимки: кнопка «Обновить сейчас» и расписание 09:00 и 21:00 по Бишкеку — pg_cron в Supabase вызывает
  `POST /api/cron/earn-snapshot` на Vercel (`pnpm earn:supabase cron-install`). Хранятся в БД, таблица
  `earn_snapshots` (2026-10-10: на Vercel нет постоянного диска, файлы `data/snapshots` больше не пишутся).

### 3.2 Портфель — где лежат деньги и куда переложить ✅
- Доступ: **read-only** API-ключ (`BINANCE_API_KEY/SECRET`), подпись HMAC на сервере.
- Источники: Spot, Funding, Simple Earn Flexible/Locked, суммы по всем кошелькам.
- Сводка: всего на Binance, сколько приносит сейчас ($/год), сколько добавит план.
- План по группам: стейблкоины считаются единым пулом, остальные монеты — каждая отдельно.
  Жадная раскладка заполняет самые доходные ступени. Затем — конкретные ходы
  («N USDT из Spot → обменять на U → U Flexible»). Locked предлагается, только если он лучше
  Flexible-плана на ≥ 0,5 п.п.; текущие Locked-позиции до конца срока не трогаем.

### 3.3 Сигналы и сделки 🚧 (план одобрен 2026-10-09)
Решения пользователя (2026-10-09): **только крипта** (акции позже); сделки **Spot + USDⓈ-M фьючерсы,
плечо ≤ 3x**; **сначала тестнет**, потом реал; рекомендации — **правила + объяснение Claude**.

Реализованные параметры правил (`src/features/scan-market/config/rules.ts`):
- вселенная — USDT-рынки с оборотом ≥ $20M (фьючерсы) / ≥ $5M (только спот), без стейблкоинов
  и плечевых токенов; анализируются топ-12 роста и топ-12 падения;
- лонг: 24 ч ≤ −7%, RSI 1h ≤ 35, цена ≤ −2 ATR от EMA50;
- шорт: 24 ч ≥ +12%, RSI 1h ≥ 70, цена ≥ +2,5 ATR от EMA50, только при наличии бессрочного фьючерса;
- стоп — за экстремумом 12 свечей 1h + 0,25 ATR (в пределах 0,8–3 ATR); TP1 — EMA20, TP2 — EMA50
  (не ближе 3R); R:R до TP1 ≥ 1;
- статус «можно входить», если последняя свеча 1h развернулась, иначе «ждём разворота»;
- размер позиции: риск % от капитала (по умолчанию 1% от $1000), лимит на сделку ($100), плечо ≤ 3x.
  Настройки лежат в URL.

**Сканер рынка** (публичные данные Binance, без ключа):
- Лидеры роста и падения за 24 ч по Spot и USDⓈ-M фьючерсам. Фильтр по обороту отсекает неликвид,
  стейблкоины и плечевые токены исключаются.
- По кандидатам загружаются свечи (1h/4h) и считаются индикаторы: RSI(14), ATR(14), EMA20/50,
  всплеск объёма, отклонение от средней, ближайшие уровни.

**Сетапы** (прозрачные правила, параметры в конфиге):
- *Отскок после падения* → лонг (Spot или фьючерс): сильное падение за 24 ч, RSI перепродан,
  объём подтверждает.
- *Перегрев после роста* → шорт (только фьючерсы): сильный рост, RSI перекуплен, всплеск объёма.
- *Продолжение тренда* → по направлению EMA (опционально).
- Для каждого сетапа: тип сделки, вход, Stop Loss (≈ 1,5×ATR за уровнем), Take Profit (TP1/TP2
  по ATR/уровням), R:R, размер позиции от риска (по умолчанию 1% капитала) и лимита на сделку.
  Сетапы с R:R ниже порога не показываются.
- Кнопка «Разбор от ИИ» ✅: модель получает данные сетапа (уровни, R:R, RSI 1h/4h, ATR, EMA, объём,
  оборот) и отвечает строго по JSON Schema: вердикт (входить / ждать / пропустить), уверенность,
  резюме, аргументы за и против, условие отмены идеи. Модель объясняет, но не принимает решение.
  - Решение 2026-10-09: ключа Anthropic нет → **OpenRouter**, модель **`anthropic/claude-haiku-5.5`**
    ($0,10 / $0,50 за 1M токенов, ≈ $0,0004 за разбор), `reasoning.effort: low`. Модель меняется
    переменной `ANALYSIS_MODEL`. Специализированные «трейдинговые» LLM не нужны: модель не
    прогнозирует цену, а разбирает уже посчитанный сетап.
  - Один и тот же сетап (те же уровни) кэшируется на 15 минут — повторный клик не оплачивается.
  - Проверено вживую 2026-10-09: ответ ≈ 10 с, ≈ $0,00035 за разбор. Соединения к OpenRouter
    из Node с этого Mac иногда обрываются до ответа (`UND_ERR_SOCKET: other side closed`) —
    клиент повторяет запрос с паузами 0,4 / 1,2 / 3 с и показывает реальную причину ошибки.
  - Демо-сделки проверены вживую 2026-10-09: Spot-лонг ETH (рынок + OCO) — ✅. Фьючерсы
    доходят до биржи (маржа/плечо ставятся), но вход отклоняется «Margin is insufficient»:
    на демо-фьючерсах нулевой баланс, его нужно пополнить на demo.binance.com.

**Риск и доступность** ✅ (запрос пользователя 2026-10-09: «риск максимум 1–2%»):
- Потеря на стопе — **не больше 2% баланса кошелька** (Spot или USDⓈ-M Futures). Поле риска
  в UI ограничено 2% (по умолчанию 1%); сервер отклоняет сделку с большим риском, а окно
  предлагает «Уменьшить количество до риска 2%».
- Капитал для расчёта по умолчанию «авто» — USDT на демо (Spot + Futures); можно ввести вручную.
- До отправки на биржу проверяется, хватает ли USDT / маржи на нужном кошельке. Пустой
  кошелёк — понятное сообщение, а не отказ биржи «Margin is insufficient».
- Скан сразу помечает, есть ли символ в Binance Demo Trading (`demoTradable`); для отсутствующих
  кнопка сделки не показывается.
- Пополнить демо-фьючерсы через API нельзя (`/sapi` на демо-хосте → 404) — только в интерфейсе
  demo.binance.com.

**Предпроверка перед сделкой** ✅ (запрос пользователя 2026-10-09):
- При открытии окна сделки сервер пересчитывает сетап по свежим свечам 1h/4h и цене (без кэша
  сканера, `POST /api/signals/recheck`).
- **Актуален** — уровни подтверждены. **Обновлён** — правила выполняются, но вход/SL/TP сдвинулись
  > 0,5%: новые уровни подставляются в заявку, объём пересчитывается с тем же риском в $
  (не больше исходного объёма), в окне видно «было → стало». **Не стоит** — цена уже за стопом,
  уже у TP1 или условия правил больше не выполняются (с перечнем, какие именно); кнопка
  подтверждения блокируется.

**Сеть:** все читающие запросы к Binance и OpenRouter повторяются при обрывах (0,4 / 1,2 / 3 с),
включая обрыв тела ответа; справочник демо-фьючерсов (~900 КБ) кэшируется, при сбое берётся
последняя удачная копия; для Spot правила грузятся по одному символу. Ордера не повторяются,
чтобы не открыть позицию дважды. Сетевой сбой больше не выдаётся за «символа нет в демо».
  - Jina AI (Reader / DeepSearch) — кандидат на будущее: подтягивать свежие новости по монете
    (листинг, взлом, разлок) в контекст разбора.

**Сделка в один клик** (только ручное подтверждение) — ✅ в демо-режиме:
- Модальное окно с заполненной заявкой: количество, SL, TP (кнопки TP1/TP2), плечо — всё можно
  поправить → «Подтвердить сделку на демо».
- Среда — **Binance Demo Trading** (demo.binance.com): виртуальные деньги, реальные котировки,
  хосты `demo-api.binance.com` (Spot) и `demo-fapi.binance.com` (Futures), один ключ
  `BINANCE_DEMO_API_KEY/SECRET`. Старый testnet Binance перенаправляет на Demo Trading.
- Spot-лонг: рыночная покупка → OCO на продажу (`LIMIT_MAKER` тейк + `STOP_LOSS` стоп)
  на купленное количество за вычетом комиссии.
- Фьючерсы: изолированная маржа, плечо ≤ 3x, рыночный вход, затем SL и TP algo-ордерами
  (`POST /fapi/v1/algoOrder`, `STOP_MARKET`/`TAKE_PROFIT_MARKET`, `closePosition`, по mark price).
- Сервер перед отправкой сам проверяет: шорт только на фьючерсах, стороны SL/TP относительно
  текущей цены демо, округление по шагам символа, минимальный объём символа и лимит
  `DEMO_MAX_NOTIONAL_USD` (по умолчанию $1000). Символа нет в демо — сделка отклоняется.
- Если вход прошёл, а TP/SL не выставились, сделка помечается «открыта без защиты» с подсказкой
  закрыть вручную. Статус и шаги попытки показываются в окне сделки и пишутся в серверный
  журнал (`trade.done` / `trade.rejected` / `trade.unprotected`).
- **История сделок — по API, локально не хранится** (запрос пользователя 2026-10-10).
  Блок «Демо-сделки» (`GET /api/trade/history`) показывает исполненные ордера с демо-счёта:
  Spot `GET /api/v3/myTrades`, Futures `GET /fapi/v1/userTrades`. Fills одного ордера
  складываются в строку (объём, средняя цена, сумма, комиссия, realized PnL фьючерсов).
  Эндпоинты требуют `symbol`, поэтому символы собираются запросами без символа: Spot —
  OCO-история `allOrderList`, открытые ордера, монеты на балансе; Futures — `income`
  (только ~3 месяца), позиции, открытые и algo-ордера. Ограничение: spot-сделка без OCO
  по монете, которой уже нет на балансе, в историю не попадёт. Отклонённые попытки
  на биржу не уходят — они только в «Логах». `data/trades/demo.jsonl` больше не пишется.
- **Статусы сделок и ссылки на график** ✅ (запрос пользователя 2026-10-10, spec
  [`001`](specs/001-trade-status-indicators.md)). У каждой строки «Демо-сделок» — индикатор статуса
  сделки (один у входа и выхода): открыта (пустой круг, контрастная окантовка), стоп подтянут
  (зелёная окантовка), без стопа (жёлтая), TP, стоп в плюс, SL, вручную в профит/лосс (квадраты),
  ликвидация, неизвестен; подсказка с SL и текущим PnL, легенда под таблицей. Пара — ссылка
  на страницу пары в Binance Demo. Статус выхода — по истории algo/OCO-ордеров, открытость — по
  позиции/балансу на бирже. Решения: строка = ордер; «скользящий SL» — только индикатор, приложение
  стоп не двигает.
- **Live** (реальные деньги) пока не реализован намеренно. План: отдельный торговый ключ
  с **ограничением по IP** (без него Binance удаляет ключи с правом торговли), явный флаг
  в `.env.local` и лимит суммы на сделку.

**Журнал:**
- Каждый показанный сигнал сохраняется. Затем по свечам проверяется, что сработало раньше — TP или SL.
  Отсюда статистика точности по каждому правилу.
- Исполненные сделки и их статусы тоже пишутся в журнал.

**Вне scope этапа:** автоторговля (её заменяет paper-лаборатория §3.4), акции, маржинальная торговля на Spot, плечо > 3x.

### 3.4 Авто-бот 🚧
Отдельный экран. Бот исполняет сигналы по правилам с лимитами риска. Включать только после того,
как журнал покажет устойчивую точность правил на тестнете.

**Автосделки (демо) — заменено лабораторией экспериментов** (spec 003, задача 3e: панель, фоновый цикл и
`/api/auto-trade` удалены; ручные демо-сделки и сводка над «Демо-сделками» остались). Было
(запрос пользователя 2026-10-10, [spec 002](specs/002-auto-trade.md)) — шаг к боту
ради статистики: переключатель на `/signals`, сервер каждые 2 мин входит в Binance Demo по всем
сетапам (ready и watch) после предпроверки; риск 1%, объём ≤ $100, плечо 2x, TP1 + SL; без повторов
(уже в сделке / пауза 2 ч). Сводка результатов над «Демо-сделками». Живой торговли нет.
Итог ночи 9→10.10: 19 закрытых, 2 в плюс / 17 в минус, −$40 — контртренд-шорты после пампа убыточны.

**Лаборатория экспериментов ✅** (запрос пользователя 2026-10-10, [spec 003](specs/003-experiments-lab.md)) —
40 paper-экспериментов (20 Spot + 20 Futures) со своими бюджетами и учётом, статистика по эксперименту/
рынку/монете/направлению, бюджет $10 000 на каждый эксперимент, сделки по $50 (решение 2026-10-10, раньше — риск 0,5%), сброс капиталов, БД Postgres (Supabase),
запуск 24/7 на **Supabase (Tokyo: БД + тик в Edge Function) + Vercel (интерфейс)** — основной вариант, Oracle Cloud Free (Dubai) — резерв ([spec 007b](specs/007b-supabase-hosting.md)); вход только через GitHub. Решения пользователя: paper +
лучшие в демо; ключ реального аккаунта на сервер не кладём.
Сброс тестовых капиталов (`/settings`, задача 3d) — новая эпоха `runs`: открытые сделки закрываются по
последней цене (нет цены — по цене входа, PnL 0, пометка `resetWithoutPrice`), старые сделки остаются
со своим `run_id`, тумблер движка не меняется. Стартовый бюджет хранится в `engine_state.next_budget` и
применяется ко всем экспериментам при сбросе. Повторный клик не создаёт вторую эпоху (`fromRunId`).
**Demo-зеркало (задача 6, [spec 008](specs/008-demo-mirror.md), решение пользователя 2026-10-11)** — галочка
«Демо-счёт» у каждого эксперимента в таблице `/experiments` (и на `/settings`) с модалкой подтверждения, отдельные демо-колонки (торговля, сделки, win rate, PnL). `/settings` разделён на «Paper» и «Binance Demo»: сброс любого эксперимента отдельно, «Сбросить все Paper» (новая эпоха), «Сбросить всё Demo». Свежие paper-входы отмеченных экспериментов раз в минуту повторяются в Binance Demo
(тот же объём ~$50, SL/TP, плечо 1) и закрываются вместе с paper-сделкой. Движок и эпоха не
останавливаются; учёт — отдельная таблица `demo_mirror_orders`. У всех заголовков таблиц — меню с
описанием колонки и сортировкой (shadcn/ui `DropdownMenu`).
**Демо-зеркало без потерь ([spec 0012](specs/0012-mirror-entry-fixes.md), решение пользователя 2026-10-15)** —
объём после округления не ниже минимума биржи; монеты, которых нет на демо, пропускаются до входа; стоп подтягивается
к фильтру цены биржи, спот входит одной заявкой OTOCO/OTO, на фьючерсах неустановленный стоп → закрытие по рынку.
Несколько зеркал на одну монету: Hedge mode на демо-фьючерсах, у каждого зеркала свои TP/SL на свой объём, лимита нет.
**Приватные эксперименты ✅** (задача 0015, [spec 0015](specs/0015-private-strategy-catalog.md), решения
пользователя 2026-10-15) — репозиторий публичный, но новые эксперименты лаборатории, их параметры и анализы
`/flow lab` — в приватном репозитории `binance-dashboard-private` (клон в игнорируемой `private/`).
Эксперимент — JSON в `private/experiments.json` (id `PS..`/`PF..`), в БД — командой `pnpm lab:private --prod` (без флага в Postgres не пишет);
дальше он виден и торгует как любой эксперимент каталога. Шифрование в публичном репо отклонено.

### 3.6 Логи и обработка ошибок ✅ (запрос пользователя 2026-10-09)
**Журнал в БД и уведомления о сбоях** (запрос пользователя 2026-10-11): журнал (info+) хранится в Postgres
(`app_logs`, 14 дней) — на Vercel нет диска. Каждые 15 мин монитор ищет сбои (ручки сыпят 5xx, всплеск
ошибок события, движок не тикает, упал cron, Earn не обновлялся), просит дешёвую модель OpenRouter коротко
объяснить причину и пишет в Telegram (@binance_dashboard_gold_bot, лично владельцу — канал не нужен).
Без спама: повтор не чаще 2 ч, «восстановлено» — один раз.

- Серверный журнал — JSON-строки в `data/logs/app-YYYY-MM-DD.jsonl` (не в git) + строка `[log] …`
  в консоли dev-сервера. Ключи, секреты и подписи маскируются (`redact`), юнит-тесты не пишут.
- Что пишется: каждый запрос к нашим API (метод, путь, статус, время); подписанные запросы
  к Binance (debug для чтения, info для записи, warn для ошибок биржи); сетевые повторы и
  восстановления (`net.retry`, `net.recovered`, `net.failed`); OpenRouter (модель, время,
  стоимость, ошибки схемы); каждая демо-сделка с шагами (`trade.done` / `trade.rejected` /
  `trade.unprotected`); сводка скана и пропущенные монеты; предпроверки; ошибки браузера
  (запросы TanStack Query, `window.onerror`, `unhandledrejection`) через `POST /api/logs`.
- Все API-роуты обёрнуты `withLogging`: непредвиденная ошибка → JSON `{ error }` (502 для сбоя
  внешнего сервиса, 500 для нашей) и стек в журнале.
- Страница «Логи» (`/logs`): фильтр по уровню, раскрытие деталей, автообновление 10 с.
- Сетевые модули Binance разделены: `@/shared/api/binance` — только типы и чистые функции
  (безопасно для браузера), сетевые запросы — `public.server.ts` / `account.server.ts` /
  `demo.server.ts`. Иначе `node:fs` логгера попадает в клиентский бандл.

**Справка на странице «Сигналы»** ✅: блок «Как читать карточки и кнопки» и подсказки на кнопках —
жёлтая кнопка сделки = «можно входить» (есть разворотная свеча), чёрная = «ждём разворота»;
нет кнопки = символа нет в демо; что даёт «Разбор от ИИ» и почему он заменяется результатом.

**Демо-счёт:** балансы берутся по API с реального демо-счёта Binance, локального учёта денег нет
(история сделок тоже загружается с демо-счёта). Начислить демо-средства нельзя — только сброс
к стартовой сумме в интерфейсе demo.binance.com (по сторонним источникам ~$5000 Spot /
~$16 800 Futures; перед сбросом отменить ордера и закрыть позиции).

## 7. Процесс разработки (решения пользователя 2026-10-10)
Подробно — `docs/ai/workflow.md`. Новое требование → `/feature`, баг → `/bug`:
Analyst (главная сессия: вопросы, PRD, ТЗ в `docs/specs/NNNN-slug.md`) → ⏸ ТЗ → Developer (субагент,
ветка `feature|bug/NNNN-slug`, код + тесты) → Tester (субагент, Playwright, скриншоты,
PASS/FAIL по критериям) → ⏸ пользователь по скриншотам → PR → Reviewer (субагент, ревью в PR,
label `ai-approved`) → ⏸ **мержит пользователь** командой `/merge`. Круги тестов и ревью — до 3, дальше
к пользователю. CI (GitHub Actions): Biome · Steiger · typecheck · Vitest · build — на каждый PR и push в
`main`. Ветка по умолчанию — `main` (без develop).
**Worktree на задачу** (решение пользователя 2026-10-15, отменяет «один чат, одна задача за раз» от 2026-10-10):
каждая задача — в своём worktree (`pnpm wt`) с локальным сервером; Tester проверяет на нём до PR и после правок по
ревью; после мержа и выкатки worktree удаляется. Процессы целиком, с мержем по команде и выкаткой, — `/flow`
(`.config/flows/*.yaml`).
**Номер задачи** (решение пользователя 2026-10-15): сквозной `NNNN` на фичи, баги, hotfix и chore; ветки
`<тип>/NNNN-slug`, коммиты `NNNN: что сделано`; история задач — `docs/HISTORY.md` (в контекст не подключается).
**Лаборатория как процесс** (решение пользователя 2026-10-15): разбор экспериментов и новые гипотезы — `/flow lab`
(`.config/flows/lab.yaml`): отчёт по сделкам эпохи `pnpm lab:report` → субагент `quant` (скилл `trading-lab`) →
⏸ решения → `pnpm lab:apply` только подтверждённое → карточки гипотез ⏸ → журнал `docs/lab/` (PR) → выбранная
карточка в `/flow feature`. Решения и критерии остановки записываются до того, как появятся данные.
