# Соглашения

## Язык
- UI, комментарии, документация, ТЗ, ревью — **на русском**. Идентификаторы — на английском, сообщения коммитов — на русском.
- Комментарий объясняет «почему», а не «что». Плотность — как в соседнем коде.

## Нейминг
- Слайсы и папки — `kebab-case`, сущности в единственном числе (`trade`, `holding`).
- Компоненты — `PascalCase.tsx`, хуки — `useXxx.ts`, остальное — `camelCase.ts`.
- Zod-схема `xxxSchema`, тип `type Xxx = z.infer<typeof xxxSchema>`.
- Query-ключ `xxxQueryKey` рядом с хуком; хук запроса — `useXxx`, мутации — `useDoXxx`/`usePlaceXxx`.
- Функции запросов к внешним API — `fetchXxx`; серверные сценарии фич — глагол (`placeTrade`, `scanMarket`).
- Константы-пороги — `UPPER_SNAKE_CASE` в сегменте `config` или вверху модуля.

## Код
- TypeScript strict, без `any` и `as` для обхода типов (исключение — разбор `unknown` из внешнего мира рядом с Zod).
- Внешние данные (HTTP-ответы, env, файлы) — только через Zod.
- Серверные данные — TanStack Query, не копировать в клиентский стейт. Фильтры/пагинация — в URL (nuqs).
- Сортировка таблиц — только localStorage, не в URL: в модуле таблицы
  `const SORT_TABLE = defineSortTable("<маршрут>:<таблица>", SORT_KEYS)`, в компоненте `useTableSort(SORT_TABLE)`
  (`@/shared/lib`). Имя — строковым литералом, повтор ловит тест (spec 009).
- Новая зависимость — только актуальная и поддерживаемая; зафиксировать причину в PR.
- Не оставлять мёртвый код, закомментированный код и `console.log` (логгер — `log.*` на сервере).

## Тесты
- Vitest, файлы `*.test.ts` рядом с модулем. Тестируем чистые функции `lib/` и схемы — без сети.
- Фича — тесты на новое поведение. Баг — **сначала падающий тест**, потом фикс.
- Имена тестов — по-русски, описывают поведение («складывает fills одного ордера…»).

## Git
- **Номер задачи** (решение пользователя 2026-10-15): у каждой задачи — фичи, бага, hotfix, chore — сквозной
  четырёхзначный номер `NNNN` (`0010`, `0011`…), один счётчик на все типы. Следующий номер — `pnpm -s wt next`:
  на 1 больше всех номеров в `docs/HISTORY.md` ветки `main` и в ветках задач, которые ещё не влиты (параллельные
  worktree). Spec задачи — `docs/specs/NNNN-slug.md` с тем же номером (старые spec `001`…`009` не переименовываем).
- **Ветки:** `<тип>/NNNN-краткое-описание`, тип — `feature`, `bug`, `hotfix` (срочный фикс прода), `chore`
  (документация, конфиги, процессы, рефакторинг без изменения поведения). Описание — kebab-case, англ.:
  `feature/0011-portfolio-chart`, `bug/0012-sort-restore`, `chore/0010-task-numbering`. Каждая ветка задачи живёт
  в своём worktree (`pnpm wt new <ветка>`, скилл `worktree`); основной checkout — только `main`.
- **Коммиты:** `NNNN: что сделано` — номер задачи, двоеточие, коротко по-русски: `0012: сортировка
  восстанавливается из localStorage`. Заголовок PR — в том же формате (он же — сообщение squash-коммита в `main`).
- **`docs/HISTORY.md`** — журнал задач для самоконтроля и истории; в контекст не подключается (без `@`,
  целиком не читать). Строку `в работе` добавляет тот, кто заводит задачу, — в её worktree, первым коммитом ветки;
  статус `✅`/`отменена` и PR проставляются последним коммитом ветки — вместе со статусом spec.
- В `main` — только через PR и `/merge` (squash). Прямой push в `main` блокирует pre-push хук.
- Автор — `Aleksandr Abramov <aleksabramov77@gmail.com>`, remote — `git@github-personal:aleksabramov77/…`.

## Pull Request
Заголовок — `NNNN: что сделано`. Тело — что сделано в задаче (решение пользователя 2026-10-15): сначала кратко,
потом подробнее. Не перечислять ветки, коммиты, номера влитых PR, отчёты о проверках и историю работы.
```
## Кратко
1–3 строки: что изменилось для пользователя.

## Подробнее
- **Добавлено:** …
- **Исправлено:** …
- **Изменено:** … (поведение, настройки; что сделать после мержа — если нужно)

Spec: docs/specs/NNNN-slug.md
```

## Definition of Done
1. Все критерии приёмки из spec выполнены и подтверждены Tester-ом и пользователем.
2. `pnpm check` и `pnpm build` зелёные, CI зелёный.
3. Новое поведение покрыто тестами; нет нарушений FSD.
4. PRD обновлён (статус требования, решения), spec — статус и ссылка на PR, строка в `docs/HISTORY.md` — ✅ и PR.
5. Сложный модуль изменён → его README актуален.
