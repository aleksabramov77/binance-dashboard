# features/paper-engine — движок лаборатории экспериментов

Домен «Лаборатория экспериментов» (spec 003, задача 1d). Paper-симуляция 40 экспериментов на публичных
свечах Binance: без ключей и без ордеров. Расчёты (стратегии, выходы, sizing, комиссии) — в ядре
`@binance-dashboard/trading-core`, здесь — тик, юниверс, кэш свечей, каталог и интерфейс хранилища.

## Среда-независимость
Тик вызывают и in-process таймер на VM Oracle (`instrumentation.ts`), и Edge Function Supabase (Deno,
spec 007b). Поэтому модули слайса импортируют только `@binance-dashboard/trading-core`, `zod` и друг
друга: без `@/…`, `node:*`, `process.env`, `fs`, таймеров, `Date.now()` и `Math.random()`. Сеть, БД
и время приходят через `TickDeps` и аргумент `now`.

## Тик
1. `engine_state.runner` ≠ своя роль (`oracle` | `supabase`, по умолчанию `oracle`) → `foreign-runner`, ничего не делаем.
   `engine_state.enabled` ≠ `true` → `disabled` (тумблер по умолчанию выключен).
2. **Выходы.** Для открытых сделок эпохи — 1m-свечи от `checkedUntil` (запрос со `startTime`, обычно
   один на символ; после простоя — страницами, см. ниже), `walkExits` ядра: тайм-стоп → SL → TP (задеты оба — SL), затем безубыток и трейлинг. Закрытие —
   `exitFill` (TP по уровню, прочее — со слиппеджем) и `settle` (комиссии, PnL, R).
3. **Сигналы.** Для каждого включённого эксперимента: если закрылась новая свеча его TF (метка
   `engine_state.bars[id]` < openTime последней закрытой свечи) — юниверс по тикерам рынка плюс символы
   его открытых сделок, свечи TF (последняя незакрытая отброшена), `evaluateStrategy` ядра.
   - выход по сигналу (`exit.exitOnSignal`) — по текущей цене, даже если свеча устарела;
   - **устаревшая свеча** (закрылась раньше `now − max(3 мин, 5% TF)`: 5m–1h — 3 мин, 4h — 12 мин,
     1d — 72 мин; первый тик после включения, рестарт, простой) — входов нет, только ставится метка;
     входим со следующей свежей свечи TF. Исключение — `hold` (S20, F20): свежесть не проверяется, и
     пока позиции нет, эксперимент пробует войти каждый тик (id сделки — по минуте);
   - вход: направление разрешено (spot — только long), часы, фильтры режима рынка и тренда старшего TF (long — цена
     выше EMA, short — ниже), `maxOpen` и одна позиция на символ, цена — `lastPrice` тикера + слиппедж ядра,
     размер — `sizePosition` (фиксированные $50 — `ENGINE.tradeNotionalUsd`, свободные деньги = бюджет +
     реализованный PnL − объём открытых); сигнал, прошедший фильтры, но упёршийся в лимит, — в журнал отсечённых
     (ниже); у сделки — снимок рынка на входе `entryContext` и `mae` = цена входа;
   - momentum (S18) — ранг доходности за `lookbackBars` среди юниверса; random — детерминированное число
     от (эксперимент, символ, свеча).
4. Метка свечи ставится после обработки: повторный тик в ту же свечу не входит снова. id сделки
   детерминирован (`run-эксперимент-символ-свеча`), `insertTrade` идемпотентна.
5. Итог тика пишется в `engine_state.last_tick`.

## Фильтры режима рынка и часов (spec 0029)
- `config.sessionFilter` — `sessionAllows` ядра по времени тика (= времени входа): вне часов/дней UTC входов нет;
  дни — по UTC-дню момента входа (окно через полночь с `days` — по дню входа, не по дню начала окна).
- `config.marketFilter` — `marketRegimeAllows` ядра по закрытым свечам `symbol` (по умолчанию BTCUSDT) таймфрейма
  фильтра. Свечи берутся через тот же `signalCandles`, что и свечи сигналов: незакрытая отброшена, один запрос
  на (market, symbol, tf) за тик для всех экспериментов, кэш между тиками. Рынок свечей BTC — рынок эксперимента
  (spot-эксперимент — spot BTCUSDT, USDⓈ-M — бессрочный BTCUSDT, COIN-M — BTCUSD_PERP: символ переводится в формат
  группы `symbolInMarket`, так что `BTCUSDT` в конфиге годится для всех групп): кэш общий с экспериментами, которые торгуют сам
  BTC, а разница цены spot/perp на close старшего ТФ для сравнения с EMA несущественна.
- Нет свечей режима (сбой запроса; меньше `regimeMinCandles` — «мало свечей режима») — вход запрещён, одна ошибка
  в `errors` тика на (рынок, символ, TF), а не на каждый эксперимент; выходы и выход по сигналу работают как обычно. Порядок проверок входа: направление и часы → режим рынка → тренд → `maxOpen` и символ (spec 0030). Сбой свечей
  фильтра тренда — как у режима: вход по символу запрещён, одна ошибка тика на (рынок, символ, TF), остальные символы
  эксперимента обрабатываются.
- Схема конфига строгая: строку `experiments` с незнакомым полем `listExperiments(onInvalid)` пропускает, тик идёт
  для остальных, в `errors` — «эксперимент <id> пропущен: …» с путём поля; её открытые сделки ждут исправления строки.

## Контекст входа, MAE и отсечённые сигналы (spec 0030)
- **Контекст входа** `paper_trades.entry_context` (jsonb, `entryContextSchema` ядра) — `computeEntryContext` ядра по
  закрытым свечам ТФ эксперимента, которые и так есть для сигнала (незакрытые к моменту входа функция отбрасывает
  сама — заглядывания вперёд нет): ATR%, ADX(14), ширина Bollinger(20, 2) %, RSI(14), объём / SMA20 предыдущих,
  расстояние до EMA200 %, изменение за 24 ч; место символа в юниверсе по обороту и размер юниверса; режим BTC —
  закрытые 4h `ENGINE.contextBtcSymbol` в формате группы (`symbolInMarket`: у COIN-M — `BTCUSD_PERP`, свечи dapi) через
  тот же `signalCandles` (кэш общий со свечами режима 0029 и сигналов: один запрос на группу за тик, только когда
  сделка открывается); funding — общий запрос тика `deps.funding(market)` своей группы (только фьючерсы: usdm, coinm;
  spot — null); час и день недели входа UTC. Нехватка истории — поле null; сбой BTC или funding — их поля
  null, вход не страдает. Сделки до spec 0030 — `{}`.
- **COIN-M** (spec 0023) поддержан целиком: контекст входа считается так же (BTC — `BTCUSD_PERP`, funding — ставки dapi,
  место в юниверсе — по обороту в $ из `coinmTicker`), MAE — по 1m-свечам контракта, отсечённые сигналы пишутся с
  `market = coinm`. Эксперимент COIN-M без размера контракта у тикера пропускает вход после проверки лимита — такой
  сигнал отсечённым не считается (нет данных, а не лимит), а упёршийся в лимит — записывается.
- **MAE** `paper_trades.mae` — худшая цена с входа: `walkExits` ядра ведёт её рядом с `extreme` (low для long, high
  для short), свеча выхода учитывается (тейк — её low/high, стоп и тайм-стоп — цена срабатывания); проход выходов
  сохраняет её вместе с `extreme`, закрытие — вместе с итогом; выход по сигналу — с ценой выхода.
- **Отсечённые сигналы** — таблица `skipped_signals`: сигнал прошёл направление, часы, режим и тренд, но сделка не
  открыта — `max-open` (лимит `maxOpen`), `symbol-busy` (символ уже в позиции у эксперимента), `no-budget`
  (`sizePosition` вернул null). Пишутся цена входа со слиппеджем, стоп и тейк, которые были бы, свеча сигнала и
  время тика; id `run-эксперимент-символ-свеча-причина` — повтор тика не дублирует. Чтобы такие сигналы были
  честными, лимит позиций проверяется после фильтров режима и тренда (для открытых сделок порядок не важен; цена —
  возможный лишний запрос свечей тренда по символу, который всё равно упрётся в лимит). hold (S20, F20) не пишет:
  «занято» — его норма.
- **Объём** (прод — Supabase Free, 500 МБ, `features/db-space`): пачка тика пишется в конце, не больше
  `ENGINE.skippedSignalsCap` (500) строк на (эпоха, эксперимент, причина) — счётчики берутся одним запросом; записи
  старше `ENGINE.skippedSignalsRetentionDays` (45) дней удаляются при записи (индекс по `at`). Строка с индексами ≈ 0,2 КБ: худший
  случай 3 × 500 × ~45 экспериментов ≈ 13 МБ на эпоху; обычно — на порядок меньше. Лимит на причину, а не на
  эксперимент: повторяющиеся `symbol-busy` (вход, который держит сигнал много свечей) не вытесняют `max-open`. Упёрлись в
  лимит — `lab:report` помечает число как нижнюю оценку.

## Только крипта в юниверсе (spec 0029)
- Spot: `exchangeInfo` не отличает токенизированные акции и металлы от монет, поэтому `isEligibleSymbol` исключает
  базы из явного списка `NON_CRYPTO` (`config/engine.ts`: PAXG, XAUT, XAU, XAG, BTCDOM и токенизированные акции/ETF
  Binance с суффиксом B — `SNDKB`, `TSLAB`, `SPYB`…). Новые листинги дописываются в список вручную.
- Фьючерсы (USDⓈ-M и COIN-M): поставщик тикеров (`src/app/server/experimentEngine.ts`, Edge Function) берёт бессрочные
  контракты `fetchPerpetuals(market, { cryptoOnly: true })` — только `underlyingType = COIN` (у dapi поле тоже есть,
  все 20 бессрочных COIN-M на 2026-10-16 — `COIN`): без индексов (`INDEX`: BTCDOMUSDT,
  ALLUSDT) и пре-маркета (`PREMARKET` — монеты до листинга на spot: особые правила контракта, нет истории, тонкая
  ликвидность). Акции и сырьё (`TRADIFI_PERPETUAL`) и так отсекает `contractType = PERPETUAL`. Подтип `RWA` не
  учитывается: его носят и настоящие монеты RWA-сектора (MANTRAUSDT, CFGUSDT) — они остаются в юниверсе, а токены
  золота PAXGUSDT и XAUTUSDT (тоже `COIN` + `RWA`) отсекает `NON_CRYPTO`: `isEligibleSymbol` действует на все группы, включая COIN-M (`PAXGUSD_PERP`).
- Уже открытые сделки по исключённым символам закрываются своими выходами: символы открытых сделок движок
  обрабатывает и вне юниверса.

## Кэш свечей и rate limit
- Тикеры — один запрос на рынок за тик; свечи TF — один запрос на (market, symbol, tf) за тик, общий для
  всех экспериментов; не больше 8 запросов одновременно.
- `TickDeps.cache` (Map по `market:symbol:tf`) хранит закрытые свечи между тиками: при новой свече
  дозагружается хвост (10 свечей) вместо 300. На VM кэш живёт в памяти процесса; Edge Function без кэша
  грузит свечи заново — но только на закрытии свечи TF, а не каждую минуту.
- **Догрузка 1m-свечей после простоя** (баг 0028). Свечи выходов запрашиваются от `checkedUntil`
  (`startTime`), а не «последние N»: разрыв до 1000 минут — один запрос, как раньше; больше — страницами по 1000
  подряд до текущей минуты. Простой движка (выключен тумблер, упал раннер, нет сети) не теряет задетый
  стоп или тейк: сделка закрывается по той свече, где уровень был задет, `extreme` учитывает весь разрыв.
  Чтобы не выбрать вес API после многодневного простоя, за тик на символ читается не больше
  `ENGINE.maxMinutePages` страниц (3 × 1000 мин ≈ 50 ч): `checkedUntil` сдвигается только по прочитанному,
  остаток дочитывают следующие тики, в журнал — `warn` `engine.minute-gap` с символом и размером разрыва.

## Решения и ограничения
- Исполнение входа — по `lastPrice` тикера в момент тика, а не по close свечи сигнала (разница — секунды).
- Выходы новой сделки проверяются со следующей минуты: в текущей 1m-свече есть цены до входа.
- MAE ведётся только с spec 0030: у сделок, открытых раньше, `mae` = null и остаётся null — их история цен до
  миграции не известна, а догружать её ради старых сделок не стали. Ручное закрытие при сбросе MAE не меняет.
- `pct` в стопе/тейке — проценты (1 = 1%).
- Плечо paper-фьючерсов — 1× (маржа = объём): объём и так ограничен 10% бюджета.
- Funding в PnL не учитывается (вторая итерация); ставка funding нужна только сигналу F14.
- Свеча TF не пришла от Binance к моменту тика — символ пропускается в этой свече.
- Ошибка тикеров рынка — свеча эксперимента не помечается и обрабатывается следующим тиком.

## Где запускается
- VM (план A): `src/app/server/experimentEngine.ts` — хранилище на Drizzle (`entities/experiment`),
  таймер раз в минуту из `instrumentation.ts`, `POST /api/cron/tick`, тумблер `GET/POST /api/experiments/engine`.
- Supabase (spec 007b): Edge Function `supabase/functions/engine-tick` — тот же `runEngineTick` с
  `runner: "supabase"`.
- Общая композиция — `src/app/server/engineTick.ts`: тик идёт в одной транзакции под
  `pg_try_advisory_xact_lock` (`entities/experiment` → `withEngineTickLock`); блокировку держит другой
  процесс — статус `locked`, тик пропускается. Чужой раннер — `foreign-runner` без записей в БД.
- Модули слайса импортируются Deno исходниками: относительные импорты — с расширением `.ts`.
- Бэктест (spec 0032): `pnpm lab:backtest` (`scripts/lab-backtest.ts`, логика — `scripts/lib/labBacktest.ts`, история —
  `scripts/lib/labHistory.ts`) прогоняет тот же `runTick` по истории — раздел ниже.

## Бэктест по истории (spec 0032)
Отсев вариантов до живой эпохи: `pnpm lab:backtest --ids F10,PF99 [--file private/experiments.json]… [--days 120]
[--split 0.66] [--exit-tf auto|1m|5m|15m] [--to <ISO>] [--out <каталог>] [--cache <каталог>] [--no-download]
[--no-control]`. Своей торговой логики у бэктеста нет — это цикл `runTick(deps, now)` с `createMemoryStore` и
историческими `TickDeps` (`createBacktestDeps`):
- **Шаг** — закрытие свечи самого короткого ТФ прогона (`now` = граница свечи): на нём закрываются свечи всех
  остальных, свеча сигнала свежая, вход — по цене на момент тика.
- **Без заглядывания вперёд по построению:** `candles` отдаёт только свечи, закрытые к `now` (незакрытую — не
  отдаёт вовсе); `tickers` — оборот и изменение за 24 ч по закрытым часовым свечам до последнего полного часа, цена —
  close часа (внутри часа — close закрытой свечи шага); `funding` — последняя выплаченная к `now` ставка истории
  `fundingRate` (нет истории — ставки нет, число таких символов в шапке; сбой загрузки — ошибка данных в шапке). Тесты на синтетике: прогон совпадает с прямыми
  вызовами `runTick` на «живых» зависимостях; будущий скачок цены не меняет сделок до него.
- **Выходы** — `runTick` просит «1m»; бэктест отдаёт свечи интервала выходов: 1m для периода ≤ 30 дней и юниверса ≤ 10
  символов у всех экспериментов прогона, включая добавленный контроль (у S19/F19 — top-30, поэтому с контролем — 5m;
  1m — `--exit-tf 1m` или `--no-control`), иначе 5m. `--exit-tf` — вручную, вплоть до 15m, но не крупнее шага тика:
  свеча выходов крупнее шага начиналась бы до входа (отказ с ошибкой). В 1m-режиме минута входа не проверяется, как в
  живом движке; в 5m/15m она входит в первую свечу. Свеча [S, S+X) отдаётся с openTime последней минуты
  S+X−1m: движок считает её закрытой ровно в S+X и проверяет со свечи входа. Приближение: внутри свечи порядок цен не
  известен — стоп и тейк в одной свече засчитываются как стоп (`walkExits`), время выхода — с точностью до свечи.
- **Юниверс:** majors и symbols — как есть; top/movers — `pickUniverse` по историческому обороту среди символов,
  которые торгуются сейчас (смещение выживших — в шапке отчёта); стейблы и не-крипто отсекает тот же
  `isEligibleSymbol`. Символ без часовых свечей в окне 24 ч (ещё не листинг) в тикерах отсутствует.
- **Хранилище:** лимит записи отсечённых сигналов и срок их хранения (защита объёма прод-БД) в бэктесте выключены.
- **Данные:** `labHistory.ts` — публичный API Binance без ключей: лимитер веса по хосту (60 % лимита: spot 6000,
  фьючерсы 2400 в минуту; fundingRate — 500 за 5 мин), пауза и повтор на 429/418 (общая для хоста). Бан дольше 10 мин или 429 после трёх пауз —
  `RateLimitStopError`, липкая для хоста: следующие запросы отклоняются без сети (каждый запрос под баном его
  продлевает), `runBacktest` прерывается после тика, отчёт не пишется, код выхода ≠ 0, повторы сетевых сбоев и 5xx. Кэш на диске вне git — `~/.cache/binance-dashboard`
  (`klines/<рынок>/<интервал>/<символ>/<YYYY-MM>.json`, `funding/…`, `symbols/<рынок>.json`): у месяца непрерывное
  покрытие, догружается только недостающее, незакрытые к загрузке свечи не кэшируются. `--no-download` — только кэш.
- **Отчёт** — `buildLabReport`/`renderLabReport` (как `pnpm lab:report`) + шапка бэктеста и «Ограничения»; контроль
  «случайный вход» группы (S19, F19) добавляется в прогон автоматически (`--no-control` — нет); `--split` — один
  непрерывный прогон, сделки делятся по времени входа: таблицы обучающей и проверочной частей и разница. В
  `report.json` — поля `backtest` (период, точность, юниверс, ошибки данных, ограничения) и `split`.
