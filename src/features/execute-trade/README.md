# features/execute-trade

Серверный слайс: исполняет сделку «в 1 клик» в **Binance Demo Trading** и отдаёт обзор демо-счёта.
Вызывается из `app/api/trade/route.ts`. Из клиентских компонентов не импортировать (секрет демо-ключа).
Клиентская часть сделки (окно, форма) — `features/trade-ticket`.

## Публичный API
- `placeTrade(request): TradeResult` — вход по рынку + защита TP/SL, пошаговый отчёт `steps`.
- `getTradeOverview()` — настроен ли демо-ключ, лимит объёма, балансы USDT и `openSymbols` — символы
  с открытой позицией или ордерами (по ним карточки сетапов помечаются «уже в сделке»).
- `getTradeHistory()` — история демо-сделок с биржи (`GET /api/trade/history`), локально не хранится.

## История и статусы сделок (`model/getTradeHistory.ts`)
1. Символы — `fetchDemoTradedSymbols` (запросы без `symbol`), не больше 40.
2. На символ: fills (`fetchDemoFills`) и ордера для статусов (`fetchDemoSymbolOrders`: futures —
   `allAlgoOrders` + `allOrders`, spot — `allOrders`); один раз — позиции futures и баланс spot.
3. `lib/groupFills.ts` — fills → ордера (`OrderAggregate`).
4. `lib/markTrades.ts` — ордера символа по времени → сделки (рост |позиции| — вход, уменьшение — выход,
   остаток < пыли — закрыта) → статус: закрытая — по типу последнего выхода (TP/SL/trailing/ликвидация,
   иначе «вручную») и знаку итогового PnL; открытая — по позиции и стопам на бирже (нет позиции —
   «неизвестен»). PnL выхода спота — от средней цены входа.
5. Не загрузились ордера/позиции символа — его строки со статусом «неизвестен», блок не падает.

## Как исполняется сделка (`model/placeTrade.ts`)
1. Конфиг демо-ключа → правила символа (`fetchDemoSymbolRules`), цена и баланс демо.
2. `lib/validateTrade.ts` — серверная проверка: шорт только на фьючерсах, стороны SL/TP относительно
   цены, округление по `tickSize`/`stepSize`, `minQty`/`minNotional`, лимит `DEMO_MAX_NOTIONAL_USD`,
   риск ≤ `MAX_RISK_PCT` баланса. Не доверять проверкам UI.
3. **Spot:** покупка по рынку → OCO на продажу (лимитный TP + стоп). Комиссия в базовом активе уменьшает
   продаваемое количество.
4. **Futures:** если по символу уже есть позиция/ордера (`fetchDemoOpenSymbols`) — `rejected` без
   запросов на изменение: Binance не меняет маржу при открытых ордерах (`-4067`), а второй вход
   перезаписал бы TP/SL первого. Иначе изолированная маржа и плечо → вход по рынку → algo-ордера `STOP_MARKET` и
   `TAKE_PROFIT_MARKET` с `closePosition` по mark price.
5. Статус: `protected` (вход + TP/SL), `unprotected` (вход есть, защиты нет — пользователь должен
   закрыть вручную), `rejected` (позиции точно нет).

## Инварианты (не ломать)
- `BinanceApiError` на входе = биржа отказала → `rejected`. Сетевой сбой/непонятный ответ на входе
  ≠ отказ: позиция могла открыться → проверить позицию на бирже (фьючерсы) или пометить `unprotected`.
  Никогда не называть сделку отклонённой, если не уверены.
- Каждая попытка логируется событием `trade.done` / `trade.unprotected` / `trade.rejected` со всеми шагами.
- Только демо-хосты (`shared/api/binance/demo.server.ts`).

## Тесты
