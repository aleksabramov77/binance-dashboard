# features/execute-trade

Серверный слайс: исполняет сделку «в 1 клик» в **Binance Demo Trading** и отдаёт обзор демо-счёта.
Вызывается из `app/api/trade/route.ts`. Из клиентских компонентов не импортировать (секрет демо-ключа).
Клиентская часть сделки (окно, форма) — `features/trade-ticket`.

## Публичный API
- `placeTrade(request): TradeResult` — вход + защита TP/SL, пошаговый отчёт `steps`.
- `getTradeOverview()` — настроен ли демо-ключ, лимит объёма, балансы USDT и `openSymbols` — символы
  с открытой позицией или ордерами (по ним карточки сетапов помечаются «уже в сделке»).
- `closeDemoPosition({ market, symbol, direction, quantity })` — закрыть демо-позицию по рынку: снять все
  ордера символа (spot — в т.ч. OCO; futures — обычные и algo), затем futures — `reduceOnly` на весь размер
  позиции, spot — продажа min(купленное, на балансе). Позиции уже нет — только снимает ордера, статус `closed`.
  Остаток дешевле `minNotional` или меньше `minQty` (`lib/validateTrade.ts → isDust`: хвост монет после комиссии,
  когда спот закрыл OCO на бирже) — пыль, биржа его не продаст (-1013 NOTIONAL): тоже `closed`, без ордера.
  Вызывает demo-зеркало (spec 008, `src/app/server/demoMirror.ts`).
  С `protectRefs` (spec 0012, PR 2b — зеркала, открытые после PR 2b) — только свои ордера: статусы своего стопа/тейка
  (`fetchDemoAlgoOrder` / `fetchDemoSpotOrderByClientId`) → `lib/closePlan.ts` (`planOwnClose`): стоящие снимаются
  (`demoCancelAlgoOrder` / `demoSpotCancelByClientId`, снятие ноги списка снимает весь список; algo — по algoId, а без
  него — по clientAlgoId, `algoLookup`); сработал свой
  (algo: `actualOrderId` или TRIGGERED/FINISHED — демо 2026-10-15: тейк FINISHED, стоп EXPIRED; спот: FILLED) —
  `closed` без ордера, если своего объёма на бирже не осталось (`closeVerdict`; остался — докрывается); иначе
  докрывается свой объём: фьючерсы — reduceOnly на min(свой, позиция в свою сторону),
  спот — min(полученное нетто − проданное своими ордерами, баланс): нетто = купленное − комиссия в монете
  (`protectRefs.netQuantity` из fills входа, иначе по ставке 0,1%, `spotNetQuantity`) — чужие монеты не продаются. Ордера других зеркал и ручные по символу не трогаются.
  Своя позиция фьючерсов — по своей стороне (`ownPosition`: Hedge — LONG/SHORT, One-way — общая в сторону сделки).
  Без `protectRefs` (старые строки, демо-сброс по ним): снимаются только защитные ордера своей стороны
  (`protectiveToCancel`: algo и reduceOnly/closePosition закрывающей стороны своего positionSide; спот —
  `spotProtectiveToCancel`, продажи), закрывается позиция своей стороны; чужие ордера символа остаются. Все ордера
  символа больше нигде не снимаются (`demoCancelAllOrders` удалён).
- `getTradeHistory()` — история демо-сделок с биржи (`GET /api/trade/history`), локально не хранится.

## История и статусы сделок (`model/getTradeHistory.ts`)
Несколько сделок по одной монете не склеиваются (spec 0012, PR 2d): ордера своей сделки узнаются по своим
`clientOrderId`/`clientAlgoId` (`bd<id>-…`, `clientIdGroup` → `DemoSymbolOrders.groups`; вход `-M`, свои TP/SL по
`actualOrderId`, своё закрытие `-C`), у открытой сделки — только её стопы. Ордер без своего id (ручной, закрытие до
PR 2d) — выход самой поздней открытой сделки дашборда той же стороны, иначе — общая последовательность стороны
позиции (Hedge — LONG/SHORT отдельно, позиция по стороне — `DemoPosition.bySide`).
1. Символы — `fetchDemoTradedSymbols` (запросы без `symbol`), не больше 40.
2. На символ: fills (`fetchDemoFills`) и ордера для статусов (`fetchDemoSymbolOrders`: futures —
   `allAlgoOrders` + `allOrders`, spot — `allOrders`); один раз — позиции futures и баланс spot.
3. `lib/groupFills.ts` — fills → ордера (`OrderAggregate`).
4. `lib/markTrades.ts` — ордера символа по времени → сделки (рост |позиции| — вход, уменьшение — выход,
   остаток < пыли — закрыта) → статус: закрытая — по типу последнего выхода (TP/SL/trailing/ликвидация,
   иначе «вручную») и знаку итогового PnL; открытая — по позиции и стопам на бирже (нет позиции —
   «неизвестен»). PnL выхода спота — от средней цены входа.
5. Не загрузились ордера символа — его строки со статусом «неизвестен», блок не падает. Позиции и баланс
   приходят тем же снимком, что и список символов (`fetchDemoTradedSymbols`): без них нет и истории.
6. Стоп считается защитой, только если он закрывающей стороны (SELL у лонга, BUY у шорта): algo-стопы
   с `closePosition` переживают ручное закрытие и иначе «прилипали» бы к следующей сделке.
7. Разворот позиции одним ордером (только futures): закрывает текущую сделку и открывает новую
   на остаток; строка ордера — «выход» с PnL закрытой сделки и статусом новой. На споте продажа больше
   купленного в окне истории просто закрывает сделку (вход за пределами истории или депозит).

### Ограничения
- История обрезана: fills — последние 100 на символ, у futures `income` — ~3 месяца. Если вход открытой
  позиции за пределами окна, частичный выход выглядит как закрытая сделка («выход без входа»).
- Spot `LIMIT_MAKER` всегда считается TP (так выставляется тейк в OCO); ручной LIMIT_MAKER вне OCO
  дашборд не ставит, по истории их не отличить.
- Запросы уходят разом: до 40 символов × 2–3 запроса (≤ ~800 веса при лимитах 6000/2400 в минуту).
  Если появятся 429 — добавить ограничение конкурентности.

## Как исполняется сделка (`model/placeTrade.ts`)
1. Конфиг демо-ключа → правила символа (`fetchDemoSymbolRules`), цена и баланс демо.
2. `lib/validateTrade.ts` — серверная проверка: шорт только на фьючерсах, стороны SL/TP относительно
   цены, округление по `tickSize`/`stepSize`, `minQty`/`minNotional`, лимит `DEMO_MAX_NOTIONAL_USD`,
   риск ≤ `MAX_RISK_PCT` баланса. Не доверять проверкам UI. Спот: деньги — по цене +0,5% (`SPOT_ENTRY_SLIPPAGE`,
   LIMIT FOK блокирует USDT по лимитной цене); стоп продаёт купленное минус комиссия 0,1%, а биржа проверяет
   его NOTIONAL **по цене стопа** (демо 2026-10-15: 30 BAT × 0,16 = $4,8 → -1013, вся заявка отклонена) —
   такой объём отклоняется заранее понятной ошибкой, а с `fitMinNotional` поднимается
   (`fitSpotStopToMinNotional`). Стоп/тейк спота за фильтром
   `PERCENT_PRICE_BY_SIDE` / `PERCENT_PRICE` (`SymbolRules.priceBand`; SELL — [avg × askDown, avg × askUp])
   подтягивается к границе с запасом 1% текущей цены (`fitToPriceBand`), в `steps` — «Стоп подтянут к границе
   фильтра биржи: X → Y» (spec 0012). На фьючерсах коридора нет: algo-триггеры фильтр не ограничивает.
3. **Spot** (`lib/spotEntry.ts`, spec 0012): покупка и защита одной заявкой — OTOCO (тейк `LIMIT_MAKER` +
   `STOP_LOSS`) или OTO без тейка (`stopOnly`). Рабочий ордер — `LIMIT BUY FOK` по цене +0,5%: отложенные
   ордера биржа ставит только после **полного** исполнения рабочего, частично исполненный IOC оставил бы
   монеты без стопа. Объём стопа/тейка — купленное минус комиссия 0,1% в монете. Биржа отклонила заявку
   (стоп за фильтром, нет денег) — монеты не куплены, `rejected`. Исход неизвестен (-1006/-1007, 5xx, сеть) —
   заявка перечитывается по своим `clientOrderId` (`lib/spotEntry.ts → tradeClientIds`: `bd<id сделки>-L/W/S/T/M`):
   нет на бирже — `rejected`, не прочитали — `unprotected`. После покупки статусы отложенных ордеров
   перечитываются (сразу они `PENDING_NEW`); стоп стоит, а тейк снят биржей — `protected` «стоп стоит, тейк
   снят биржей», ничего не перевыставляется; снят стоп — сначала адресно снимается свой тейк того же OTOCO
   (`-T`, держит монеты; `lib/tradeOutcome.ts → afterStopLost`): исполнен — позиция уже продана; снять не удалось —
   `unprotected` без продажи; затем стоп/OCO отдельно (`-S2/-T2`), при отказе — продажа по рынку. Если OTO/OCO по символу запрещены (`otoAllowed`/`ocoAllowed` в exchangeInfo) — покупка по рынку →
   OCO/стоп → при отказе биржи продажа по рынку (`rejected` «стоп не принят»).
4. **Futures** (`model/placeFutures.ts`, spec 0012 PR 2c) — работает в обоих режимах позиций:
   - режим — `fetchDemoPositionMode` (кэш 30 с). Счёт уже в Hedge — работаем в Hedge. One-way: автопереключение
     за флагом `config/trade.ts → FUTURES_AUTO_HEDGE` (**выключено** до «окна обслуживания»: Hedge на демо не
     проверен) — без флага POST `/fapi/v1/positionSide/dual` не вызывается никогда; с флагом и пустым счётом (нет
     позиций и ордеров, обычных и algo) перед входом включается Hedge (`demoEnableHedgeMode`, `-4059` — не
     ошибка); счёт не пуст или переключить не вышло (`-4067/-4068`) — вход в One-way. Выбор — `lib/futuresMode.ts → choosePositionMode`,
     шаг «Режим позиций» в отчёте;
   - ручной вход (/signals): своя сторона занята (`ownSideBusy`: Hedge — позиция/ордера своего positionSide,
     One-way — любые по символу) — `rejected` без запросов на изменение. Вход зеркала (`TradeRequest.mirror`, PR 2d)
     делит монету и сторону с другими зеркалами (у каждого свои TP/SL на свой объём); в One-way мешает только
     встречная позиция («нужен Hedge mode»);
   - изолированная маржа и плечо; по символу уже есть ордера/позиция (`-4047/-4048`, демо отвечает `-4067`) — тип
     маржи не меняется, вход идёт дальше;
   - вход по рынку (Hedge — `positionSide`), затем algo `STOP_MARKET` и `TAKE_PROFIT_MARKET` **на свой объём**
     (`quantity`, без `closePosition`; One-way — `reduceOnly`, Hedge — `positionSide`; параметры —
     `shared/api/binance/positionMode.ts`). Стоп не встал — откат: reduce своего объёма своей стороны и снятие своего
     стопа по ссылке (если исход был неизвестен), ордера символа не трогаются: `rejected` без цены входа; не
     закрылась — `unprotected`. Стоп встал, тейк нет — `protected`;
   - «стоп до входа» (AC10) — `config/trade.ts → FUTURES_STOP_BEFORE_ENTRY` (выключено), только Hedge
     (`futuresSequence`): стоп на объём заявки, не встал — вход не отправляется; на демо не проверено;
   - общий срок сделки `TRADE_DEADLINE_MS` (60 с): перечитывания с неизвестным исходом обрываются по нему
     (`recheckStep` → giveUp — «нет» не окончательно, статус `unprotected`, а не `rejected`), тейк после срока не
     ставится; стоп и откат пробуются всегда. Дедлайн перечитывания algo — от последней попытки после повторов.
5. Опции заявки (для demo-зеркала): `fitMinNotional` — объём чуть ниже `minNotional` поднимается до минимума
   (≤ ×3, `lib/validateTrade.ts → fitToMinNotional`); `stopOnly` — без тейка: spot `STOP_LOSS` вместо OCO, futures —
   только `STOP_MARKET`. Algo-ордер с `-4509` и закрытие `reduceOnly` с `-2022` (позиция ещё не видна сразу
   после входа) повторяются через 1 и 2 с. `fitMinNotional` смотрит на объём уже после округления вниз к шагу
   (BTCUSDT $50 → 0,0006 BTC ≈ $48,99 → поднимается до 0,0007).
6. `TradeResult.protectRefs` (`shared/api/binance/protectRefs.ts`) — свои защитные ордера: фьючерсы — `entryOrderId`,
   algoId/clientAlgoId стопа и тейка (`bd<id>-S/-T`); спот — orderListId и orderId/clientOrderId стопа и тейка
   (OTO/OTOCO — `-S/-T`, отдельная защита после покупки — `-S2/-T2`). У `rejected` — null. Зеркало хранит их в
   `demo_mirror_orders.protect_refs`. Фьючерсный вход — со своим `newClientOrderId` (`-M`): при неизвестном исходе
   сначала сверка по нему (`fetchDemoFuturesOrder`), потом по позиции. Стоп/тейк с неизвестным исходом постановки перечитываются по своему
   `clientAlgoId` до дедлайна (`afterAlgoUnknown`): не нашёлся — не подтверждён (стоп → откат), но ссылка
   `{algoId: null, clientAlgoId}` сохраняется, и закрытие снимет висящий ордер. Цена входа/выхода фьючерсов без `avgPrice`
   в ответе — из ордера или его исполнений (`model/futuresFillPrice.ts`), а не текущая.
7. Выбор исхода по результатам шагов — чистые функции `lib/tradeOutcome.ts` (`afterEntryError`, `afterPending`,
   `afterProtect`, `afterFuturesRollback`…); в `model` — только запросы и шаги отчёта.
8. Статус: `protected` (вход + стоп; тейк, если он есть в заявке и встал), `unprotected` (вход есть, защиты нет и откат не удался — пользователь
   должен закрыть вручную), `rejected` (позиции точно нет, в т.ч. после отката).

## Инварианты (не ломать)
- Ошибка ордера классифицируется одним местом — `orderErrorOutcome` (`shared/api/binance/orderOutcome.ts`):
  `BinanceApiError` 4xx = биржа отказала → `rejected`. Коды «исход неизвестен» `-1006`/`-1007`, HTTP 5xx,
  сетевой сбой, непонятный ответ ≠ отказ: позиция могла открыться → фьючерсы — проверить позицию, спот —
  перечитать заявку по `clientOrderId`, не вышло — `unprotected`. Ордера входа уходят с `recvWindow` 5 с
  (`ORDER_RECV_WINDOW_MS`), проверки — раз в секунду, вердикт «заявки/позиции нет» — только по проверке, начатой
  после `отправка + recvWindow + 1,5 с` и не раньше 3 с после ответа (`unknownOutcomeDeadline`). Стоп не найден
  при перечитывании — защита не подтверждена (`unprotected`), даже если тейк стоит. То же для защиты спота:
  исход неизвестен — не продаём (стоп мог встать), `unprotected`. Никогда не называть сделку отклонённой,
  если не уверены.
- Каждая попытка логируется событием `trade.done` / `trade.unprotected` / `trade.rejected` со всеми шагами.
- Только демо-хосты (`shared/api/binance/demo.server.ts`).
