# @binance-dashboard/trading-core

Автономное торговое ядро лаборатории экспериментов (spec 003). Требование пользователя 2026-10-10:
логика стратегий живёт отдельно от UI и приложения.

## Что внутри
| Модуль | Что делает |
|---|---|
| `indicators/` | EMA, RSI, ATR, SMA, Bollinger, MACD, ADX, Supertrend, Donchian |
| `experiment.ts` | Zod-схемы эксперимента (вход, выход, юниверс, фильтры тренда, режима рынка и часов), paper-сделки (с контекстом входа и MAE) и отсечённого сигнала; группы активов `MARKETS` — `spot` / `usdm` / `coinm` и их вид `MARKET_KIND` (фьючерсы: шорт, плечо, funding); `legacyMarketSchema` читает старое имя `futures` как `usdm` (spec 0023) |
| `context.ts` | `computeEntryContext` — снимок рынка на входе по закрытым свечам (spec 0030) |
| `filters.ts` | `marketRegimeAllows` — режим рынка по закрытым свечам BTC старшего ТФ; `sessionAllows` — часы и дни UTC |
| `strategies.ts` | `evaluateStrategy(rule, ctx)` — сигнал входа и флаги выхода на закрытой свече |
| `exits.ts` | `walkExits` — проход по 1m-свечам: тайм-стоп → SL → TP, безубыток и трейлинг (дистанция — `trailAtr × (atr / entryPrice) × extreme`, баг 0041); лучшая (`extreme`) и худшая (`mae`) цена |
| `sizing.ts` | `sizePosition` — фиксированный объём (движок: $50) или риск 0,5% бюджета с лимитом 10%; не больше свободных денег; COIN-M (`contractSizeUsd`) — целые контракты, минимум 1, количество в монете = контракты × размер / вход |
| `fills.ts` | проскальзывание 0,05%, комиссии spot 0,1% / USDⓈ-M и COIN-M 0,05%, PnL и R (у COIN-M — в $ по тем же формулам: PnL инверсного контракта по цене выхода равен линейному) |

## Где UI стратегий
Требование пользователя 2026-10-10 (уточнение): стратегии — отдельная сущность; UI у неё может быть, но
только свой, без связей с авторизацией, другими дашбордами и прочим приложением. Поэтому:
- **ядро** (этот пакет) — расчёты без React: его может запускать и фоновый воркер на VM без UI;
- **UI сущности** — FSD-слайс `src/entities/experiment` (`ui/` — карточки, бейджи, описание конфигурации).
  Он импортирует только этот пакет и `shared`; импорт `features/*` (в т. ч. авторизации), `widgets/*`
  и других сущностей запрещают Steiger и Biome.

## Правила
- Только чистые функции и Zod. Нельзя: React, Next.js, `@/…` (код приложения), сеть, БД, `process.env`,
  `Date.now()` и `Math.random()` внутри функций — время и случайность передаются аргументами.
  Импорты UI и приложения запрещает Biome (`overrides` в `biome.json`).
- Зависимость направлена в одну сторону: приложение (`src/`) и будущий воркер на VM импортируют
  пакет, пакет не знает о них.
- Каждая функция покрыта тестами (`*.test.ts` рядом, запускаются общим `pnpm test`).

## Схема конфига и фильтры входа (spec 0029)
- **Строгая схема.** Объекты конфига (`config`, варианты входа, выход, варианты стопа и тейка, юниверс, фильтры) —
  `z.strictObject`: неизвестное поле (опечатка `marketFiltr`) — ошибка валидации с путём, а не молча отброшенное
  поле. Верхний уровень `experimentSchema` не строгий: им разбираются строки БД с лишними колонками. Строгость
  действует на записи (сид каталога, `lab:private`); при чтении строк БД приложение разбирает их построчно и
  пропускает невалидную строку с предупреждением (`entities/experiment`, `parseExperimentRows`).
- **`marketFilter`** `{ symbol = "BTCUSDT", timeframe, ema, minAdx?, long, short }`: вход в направлении разрешён,
  если на последней закрытой свече `timeframe` close символа выше (`above`) / ниже (`below`) EMA(`ema`) или
  условия нет (`any`), а при `minAdx` — ещё и ADX(14) ≥ `minAdx`. Незакрытую свечу отбрасывает вызывающий
  (движок — `closedCandles`), поэтому фильтр не заглядывает вперёд. Свечей меньше `regimeMinCandles(filter)`
  (период EMA; для ADX — 2 × 14) — вход запрещён. `ema` ≤ `REGIME_MAX_EMA` (250): движок хранит 300 свечей.
- **`sessionFilter`** `{ hoursUtc?: [from, to), days?: 0–6 }`: вход только в эти часы и дни по UTC; `from > to` —
  окно через полночь (`[22, 6)`), `[0, 24)` — весь день, `from = to` и пустой фильтр — ошибка схемы. Дни
  проверяются по UTC-дню момента входа: окно через полночь вместе с `days` смотрит на день входа, а не на день
  начала окна.
- Фильтры ограничивают только входы: выходы открытых сделок работают как обычно.

## Контекст входа и MAE (spec 0030)
- **`computeEntryContext`** — снимок рынка на входе в `PaperTrade.entryContext` (`entryContextSchema`): по закрытым к
  моменту входа свечам ТФ эксперимента (незакрытые функция отбрасывает сама) — ATR(14)/close %, ADX(14), ширина
  Bollinger(20, 2) %, RSI(14), объём свечи / SMA20 объёма 20 предыдущих свечей (как у `volumeSpike`), close/EMA200 − 1 %,
  изменение за 24 ч (к свече ровно на 24 ч раньше); по закрытым 4h BTC — выше ли close EMA200, ADX(14), изменение за
  24 ч; плюс funding, место в юниверсе (передаёт движок), час и день недели UTC. Индикатору не хватило истории — null
  (ATR и RSI — 15 свечей, ADX — 28, Bollinger — 20, объём — 21, EMA200 — 200). Числа округлены до 4 знаков, funding —
  нет. Схема не строгая и все поля необязательны: сделки до spec 0030 хранят `{}`, новые поля не ломают старый код.
- **MAE** — `OpenPosition.mae` / `WalkResult.mae`, худшая цена с входа (low для long, high для short). В отличие от
  `extreme`, свеча выхода учитывается: при тейке — её low/high (стоп в ней не задет, провал мог быть до тейка), при
  стопе и тайм-стопе — цена срабатывания (дальше позиции нет). `mae = null` — история не известна (сделка до spec 0030),
  остаётся null. `worseMae` — та же логика для выхода по цене (сигнал).
- **Отсечённый сигнал** — `skippedSignalSchema`, причины `SKIP_REASONS`: `max-open`, `symbol-busy`, `no-budget`.
