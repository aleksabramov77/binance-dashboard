Описание бага от пользователя: $ARGUMENTS

Конвейер тот же, что в скилле `feature` (`.claude/skills/feature/SKILL.md`) — прочитай его и выполняй
шаги 2–6 без изменений. Отличается только шаг 1 и требования к Developer.

## 1. Analyst (баг)
1. Собери факты сам, прежде чем спрашивать: строки из `data/logs/*.jsonl` (или страница `/logs`),
   связанный код, `git log` по затронутым файлам.
2. Уточни у пользователя (`AskUserQuestion`) только недостающее: шаги воспроизведения, ожидаемое поведение,
   серьёзность (по умолчанию `major`).
3. Создай `docs/specs/NNN-slug.md` по `docs/specs/_template-bug.md` (следующий свободный NNN).
   PRD меняй, только если баг означает изменение требования; иначе — строка в журнале этапов не нужна.
4. ⏸ Покажи пользователю краткое описание (шаги, ожидаемое, AC) и получи «да».

## Особенности для Developer
Передай явно: «Сначала тест, который воспроизводит баг и падает; потом фикс; заполни раздел „Причина“
в spec». Ветка `fix/NNN-slug`, коммит `fix: …`.

## Tester
Помимо AC — пройти исходные шаги воспроизведения и подтвердить, что баг не повторяется.
