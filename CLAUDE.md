# Binance Dashboard

- Концепция, требования, этапы и журнал работ — в `docs/PRD.md`. Читай его перед началом работы.
- Документация для AI — `docs/ai/` (начни с `docs/ai/README.md`): архитектура, соглашения, конвейер.
  Перед правкой сложного модуля читай его `README.md` (`src/shared/api/binance`, `src/features/execute-trade`,
  `src/features/scan-market`) и обновляй его, если меняешь устройство модуля.
- После каждого этапа или изменения требований обновляй PRD: статус этапа, коммит, новые решения и открытые вопросы.

## Как делаются изменения
- Новое требование → `/feature <требование>`, баг → `/bug <описание>`: Analyst → Developer → Tester →
  PR → Reviewer (см. `docs/ai/workflow.md`). Мерж — только пользователь через `/merge <PR>`.
- Целиком, вместе с мержем по команде и выкаткой, — `/flow feature "<…>"` / `/flow bug "<…>"`; только выкатка
  влитого — `/flow release`; незавершённые прогоны — `/flow status`. Разбор экспериментов, применение решений и новые гипотезы —
  `/flow lab ["<фокус>"]`: агент `quant`, скилл `trading-lab`, отчёт `pnpm lab:report` (чтение БД), тумблеры `pnpm lab:apply`
  (только подтверждённое пользователем), память и прогоны — `private/lab/`. Процессы — `.config/flows/*.yaml`,
  исполняет общий скилл `flow`. Claude запускать из папки проекта, а не из `~/Projects/my`.
- Мелочи (опечатка, текст, документация) — без конвейера: ветка `chore/NNNN-…` + PR.
- **Конец сессии** (решение пользователя 2026-10-15): последнее сообщение любой сессии, где что-то менялось (фича, баг,
  chore, `/merge`, `/flow release|lab|worktree-cleanup`), — яркий блок «🎉✅ СЕССИЮ МОЖНО ЗАКРЫВАТЬ ✅🎉» или
  «⛔ СЕССИЮ ПОКА НЕ ЗАКРЫВАТЬ» по шагу «8. Закрытие сессии» из `.claude/skills/feature/SKILL.md`: хвосты проверены,
  другие сессии оповещены о том, что их касается. Согласованная с пользователем и не выполненная работа (план,
  очередь, «сделаю следом») — хвост, а не «Дальше»: пока она есть — только ⛔. Такая работа сразу записывается в
  `docs/PRD.md` → «Очередь задач», чтобы не потерялась, если сессию закроют (решение пользователя 2026-10-15).
- **Номер задачи** (решение пользователя 2026-10-15): у каждой задачи сквозной номер `NNNN` — `pnpm -s wt next`
  (последний в `docs/HISTORY.md` + 1 с учётом ещё не влитых веток). Ветка — `feature|bug|hotfix|chore/NNNN-short-slug`,
  коммиты и заголовок PR — `NNNN: что сделано` (по-русски). Строку задачи в `docs/HISTORY.md` добавить при заведении
  и закрыть (✅, PR) последним коммитом ветки. `docs/HISTORY.md` в контекст не подключать и целиком не
  читать — только дописывать. Подробно — `docs/ai/conventions.md` → «Git».
- В `main` напрямую не коммитить и не пушить — только ветка + PR.
- **Каждая задача — в своём worktree** (решение пользователя 2026-10-15, отменяет «один чат, без worktree» от
  2026-10-10). `pnpm wt new feature/NNNN-slug` создаёт `~/Projects/my/binance-dashboard_NNNN-slug`: ветка от
  свежего `main`, ссылка на `.env.local`, зависимости (скилл `worktree`); spec, PRD и строка журнала задачи пишутся
  уже в нём. Основной checkout всегда на чистом `main` — в нём только мерж и выкатка, ветки там не переключать.
  Встроенные `EnterWorktree`/`--worktree` и голый `git worktree add` не использовать.
- Перед PR и ещё раз после правок по ревью задачу проверяет агент-тестировщик на локальном сервере её worktree
  (`pnpm wt serve`: своя PGlite, вход выключен, прод не трогается). После мержа и выкатки worktree удаляется
  (`pnpm wt remove <ветка>`); забытые worktree давно влитых задач удаляет хук `SessionStart` (`pnpm wt prune`).
- Перед отчётом о готовности: `pnpm check` и `pnpm build` зелёные.
- **Приватные эксперименты** (решение пользователя 2026-10-15, spec 0015): репозиторий публичный. Параметры,
  гипотезы и результаты приватных экспериментов и анализы `/flow lab` — только в `private/` (клон приватного
  репозитория `binance-dashboard-private`); не писать их в публичные файлы, spec, тесты, коммиты, описания PR и
  issue. Новые эксперименты лаборатории — в `private/experiments.json` + `pnpm lab:private --prod` (запись в прод), не в `catalog.ts`.
  Подробно — `docs/ai/architecture.md` → «Приватные эксперименты», `docs/ai/conventions.md`.
- **`.env.example` и `.env.local` — одинаковые по структуре** (решение пользователя 2026-10-11): тот же порядок,
  разделы и комментарии; различаются только значения и то, какие строки по умолчанию раскомментированы.
  Новый параметр — сразу в оба файла с одинаковым комментарием (где взять, зачем, где ещё задаётся — Vercel,
  Vault). Значения из `.env.local` не выводить. Незаполненный в `.env.local` параметр — закомментированная
  строка `# ИМЯ=НЕ_ТРЕБУЕТСЯ (причина или значение по умолчанию)`; раскомментированной её не оставлять —
  приложение прочитает слово как значение.
